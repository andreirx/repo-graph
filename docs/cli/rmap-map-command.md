# `rmap map` — deterministic MAP.md from the index

**Slice:** MAP-FROM-INDEX-1. **Status:** shipped (read/render only).

`rmap map` renders `MAP.md` orientation files **deterministically from the
current READY snapshot's extracted facts** — no LLM, no model call anywhere in
the path. It exists to honor VISION commitment #1 (*facts are computed from
source, reproducible, never model output*): the same snapshot always produces
**byte-identical** maps, and each map states its provenance.

It supersedes the LLM structure path in `tools/rgistr` (which produces
"somewhat bad" structure on a local model where the facts are already
deterministically available). rgistr's model-synthesized *prose* has no
deterministic equivalent; its structural `MAP.md` generation is deprecated in
favor of this command. Full prototype retirement tracks under
`TS-PROTOTYPE-RETIREMENT-1`.

## Invocation (REG-1: repo resolved from cwd)

```bash
rmap map [path] [--dry-run] [--json]
```

- `path` — a **repo-root-relative** directory to render (e.g.
  `rust/crates/rgr`, `src/core`). Omitted → the whole repo. The write path is
  anchored at the **resolved repository root** (returned by the daemon), so maps
  land at their repo-root-relative locations no matter which directory you run
  from — a nested cwd never recreates whole-repo paths beneath it.
- `--dry-run` — print the rendered files to **stdout** (summary to stderr),
  **write nothing**. The tree-safe path for previewing and for live
  determinism checks (`rmap map <dir> --dry-run` twice → empty diff).
- `--json` — machine envelope: `{command, snapshot, path, unmapped_count,
  files: [{rel_path, contents}]}`.

Default (no flag) **writes** the `MAP.md` files to disk, overwriting any
existing ones (a MAP is a regenerable artifact; the marker warns humans off
hand-editing it).

## Placement + marker (mirrors rgistr's shipped conventions)

- **Per-directory map:** `<dir>/MAP.md`.
- **Per-file map:** `<dir>/<base>_<ext>_MAP.md` — only the *final* extension dot
  becomes `_`; internal dots are preserved (`vitest.config.ts` →
  `vitest.config_ts_MAP.md`), matching rgistr's `fileMapFilename` (Node
  `path.extname`/`basename` semantics). A per-file map is emitted **only for
  files the index successfully parsed**.
- **Marker (first line of every file):**
  `<!-- generated by rmap map from snapshot <short-uid>; do not hand-edit -->`
  where `<short-uid>` is up to **12 chars of the snapshot uid's trailing
  content-hash segment** (the part after the last `/`), NOT the uid prefix — the
  prefix is the repo uid, shared by every snapshot of the repo. Taking the
  content hash ties the map to the exact indexed content: identical content
  re-indexed → same token → same maps. (A uid with no `/` falls back to its
  12-char prefix; an empty uid → `unknown`, never a fabricated id.) No YAML
  frontmatter (rgistr stripped that 2026-07-10; this carries the snapshot
  provenance the old header lacked). Files end with exactly one trailing
  newline.

## Content — extracted facts only (Layer 0/1), reader-frame

Unlike rgistr's LLM output (`# Purpose`, `# Likely Change Reasons`, `# Legacy
Analysis` — model synthesis), `rmap map` renders **only deterministic facts**.
*What the index does not know, the map does not say.*

**Per-file map:**
- `Language:` and, where measured, `Complexity:` (cyclomatic, summed over the
  file's symbols).
- `## Symbols` — each symbol as `name (kind, L<line>)` plus its declaration
  **signature** in backticks when the substrate has one (`nodes.signature`).
- `## Imports` — the file's imports, split into two labelled groups so no import
  is silently dropped: **Resolved intra-repo** (import edges resolving to an
  indexed file) and **External / unresolved** (the specifier the source wrote —
  external package or missing path — from `unresolved_edges`). "resolved target
  where known" (slice §1.3).
- `## Complexity coverage` — the same coverage note (below), repeated so each
  file map is self-contained: a file whose complexity is absent (unmeasured
  language, or coverage unavailable) explains itself rather than reading as zero.

**Per-directory map:**
- Repository name + **package identity** (nearest manifest root: crate / TS
  package), when known.
- `## Files` — the directory's **direct** file inventory (symbol count,
  complexity, language, test/generated flags).
- `## Subdirectories` — an index of immediate child directories that also have
  maps, so an agent walking the tree from a parent/rollup directory is never
  handed a dead end. (Ancestor directories whose code lives only in descendants
  still get a map — mirroring rgistr's `getFoldersForGeneration`.)
- `## Dependencies` — the directory's resolved intra-repo dependency footprint
  from **import AND call edges** (slice §1.3), deduped to target files. The
  section is explicitly labelled as the **resolved** subset; external/unresolved
  imports appear in each file's map, not here. Self-file edges (same-file calls)
  are excluded — they are not an inter-file dependency.
- `## Unmapped files` — files present in the index but **not** parsed for
  symbols, each **listed with the reason**, distinguishing size-cap (`skipped —
  exceeds the size cap`, from `extractor = 'skipped:oversized'`) from
  no-extractor (`skipped — no extractor for this language`) from parse failure.
  The map never silently omits a file that exists.
- `## Complexity coverage` — the per-language measurement-coverage caveat when
  coverage is partial, or the explicit reason when coverage is **unavailable**
  (never dropped), so complexity numbers — and their absence — are never read as
  complete/zero (METRIC-LANG-COVERAGE).

## Guarantees

- **Deterministic:** the renderer imposes a **total** order on everything (files
  by path; symbols by line, then name, then kind, then signature — every rendered
  field, so two rows tied on line+name cannot permute the bytes; imports/deps by
  target; directories by path; the emitted file set by output path). Identical
  facts → byte-identical output, independent of the order the daemon returned
  rows in.
- **Honest coverage:** unknown is never rendered as zero; unmeasured complexity
  is stated (per-language caveat), not silently dropped; skipped files are
  listed, not hidden.
- **No model output:** there is no LLM in the path. Every byte traces to an
  extracted fact + a fixed template.

## Under the hood

- CLI (`rgr/src/commands/map.rs`) requests the daemon `map` method (the daemon
  owns snapshot state — clients never read storage directly).
- The daemon handler (`daemon-runtime/src/handlers/map.rs`) gathers **flat**
  facts from the READY snapshot via read-only bulk projections
  (`map_files_in_path`, `map_symbols_in_path`, `map_resolved_dep_edges_in_path`
  — IMPORTS + CALLS — and `map_unresolved_imports_in_path` in
  `storage/src/queries.rs`) plus the existing `query_complexity_by_file`,
  `list_manifest_roots`, and the shared `measurement_coverage` block. It also
  returns the resolved absolute repo root for the write path. It holds no domain
  logic.
- The pure renderer (`rgr/src/presentation/map.rs`,
  `render_maps(&MapFacts) -> Vec<RenderedMapFile>`) does all grouping, ordering,
  coverage honesty, the dependency sketch, and the markdown. Being pure, it is
  unit-tested without a daemon (byte-determinism, marker + provenance, unmapped
  honesty, stable ordering under permuted input, golden fixture).

These reads are **additive and read-only** (no schema change, no write path, no
extractor change), following the direct-storage-read pattern already used by
`stats`/`imports` (RR1_BOUNDARY precedent).
