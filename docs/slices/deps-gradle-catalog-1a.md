## 2. Contract

### 2.1 The fix, at the cause — scope every block; attribute by Gradle project
(1) `config.rs` — the scope-aware extractor (DGC-A01's EXTRACTOR paragraph is the rule): only DIRECT blocks declare — a top-level `dependencies {` (`own`), a direct child of a top-level `allprojects {` / `subprojects {` (those scopes), a direct child of a top-level `project('<path>') {` (`projects[<path as written>]`); every other `dependencies {` block (inside `buildscript`/`pluginManagement`, under a condition, callback, task or extension, or under a scope head that is not at the top level) declares nothing; coordinate mining unchanged; `None` only for an unclosed block (as today) or when the script has neither a direct block carrying a coordinate nor a counted block (item 5) — a buildscript-only script changes from `Some` to `None`, and a script whose only `dependencies` blocks are counted returns empty scopes with their lines, so its marking is never lost (grpc-java `bom/build.gradle:15`; DGC-A01's EXTRACTOR paragraph is binding). (2) `manifest_deps.rs` — the per-project attribution (DGC-A01's RESOLVER paragraph): the file's Gradle BUILD (the outermost ancestor settings file in which a non-root project contains the file, else the nearest ancestor settings file), its PROJECT R (deepest containing project, through the public `parse_settings_gradle` with its `projectDir` relocations), and R's declared set = R's script's `own` ∪ the `allprojects` blocks of R and its Gradle-path ancestors in the build ∪ the `subprojects` blocks of R's strict ancestors ∪ every build script's `project(…)` blocks naming R (absolute, or relative to that script's project); a script outside every settings project, or with no settings file above it, is a single-project build (`own` ∪ `allprojects`); an unreadable settings file or `unhandled_project_dirs > 0` → FAILED record naming the cause, empty set; provenance records the nearest script as today; no probe-directory cache sharing across projects. (3) `invalidation.rs` — `settings.gradle.kts` joins `RECOGNIZED_CONFIGS`. (4) `INDEXER_VERSION` one minor up from HEAD's with its compose.rs copy. (5) The marking (D-DGC-CONDITIONAL-1; DGC-A01 and DGC-A06 are the rules): the extractor also returns the lines of the non-direct blocks it could not evaluate — the COUNTED class: not under a tooling head (`buildscript`, `pluginManagement`) or a task/extension head (`shadowJar`, `tasks.…`, `task <name>`); per Gradle build the count of those skipped BLOCKS (not declarations) and the first location ride exactly one provenance record as `undetermined_blocks {count, first}`; the daemon's `deps list` view sums the counts over the view ecosystem's records into `declared_undetermined_blocks` / `declared_undetermined_note` (only over tracked provenance); `rgr` renders the note after the coverage line and the ` (declared set incomplete)` suffix on every nonzero `undeclared` count. Direct declarations stay known — a counted block never makes a record FAILED. (6) Nothing else: no catalog parsing, no `.`-segment matching (1B), no other consumer change, no Maven change (`pom.xml` stays unparsed; the headline `⚠ Maven manifests are not parsed on this build` is unchanged).

This covers the whole scoping clause of L13 for every Gradle build the index can see: the root build and each nested build that carries its own settings file, with scope blocks read from every project script of the build — root and intermediate — not only the root script (review-0 F-DGC-01).

Local decisions recorded (within L13's authority, challengeable at review):
- "Direct" (L13: "P's own build script's direct `dependencies` block") is read literally: a `dependencies` block counts only as a direct child of the script top level or of a top-level scope block. A block under a condition or callback (`if (…)`, `afterEvaluate`, `plugins.withId(…)`), a task or a plugin extension (`shadowJar { dependencies { … } }` is a shadow-jar filter, not a declaration) is never declared, because the index cannot establish that the condition holds (review-0 F-DGC-02; RG-REQ-002-L01/L11). Its cost is a false negative — a conditionally declared group can read `observed_but_undeclared` — the class the reader documents for catalog aliases (manifest_deps.rs:84-90), never a fabricated declaration; unlike revision 1 it is no longer silent: the block is counted and `deps list` marks the declared set incomplete (D-DGC-CONDITIONAL-1; review-1 F-DGC-05). Corpus effect on declared sets in 1A: none — no non-direct `dependencies` block in kafka (`build.gradle:518` `subproject.dependencies { mockitoAgent libs.mockitoCore }` under `subprojects { afterEvaluate { subproject -> if (hasMockitoCore) { … } } }`; `:1955` under `project(':clients') { shadowJar { … } }`), grpc-java (the four under `build.gradle:14 subprojects {`, `bom/build.gradle:15`, the five `tasks.named("shadowJar").configure` blocks) or petclinic carries a literal coordinate; the marking is what changes (kafka 1, grpc-java 5); the one real declared-set loss appears in 1B: grpc-java's `subprojects { plugins.withId("java") { dependencies { testImplementation libraries.junit, libraries.mockito.core, libraries.truth } } }` (build.gradle:219-224), which 1B may admit only with evidence that the plugin applies (§8).
- A composed or non-top-level scope head (`subprojects { project(':x') { … } }`, `if (c) { subprojects { … } }`) is never attributed rather than guessed — and its block is counted (marked); none in the three corpora.
- The counted class (D-DGC-CONDITIONAL-1): the record names blocks "under a condition or callback" and excludes the tooling classpath and task/extension blocks. The slice states the two EXCLUSION lists as closed (tooling: `buildscript`, `pluginManagement`; task/extension: a head that is `shadowJar`, begins with `tasks.`, or is `task <name>` / `task(<…>)`) and counts every other non-direct block — conditions, callbacks, control flow (`try`, which encloses grpc-java :467), composed scope heads, receiver-qualified heads and any head not listed (a Kotlin-multiplatform `kotlin { sourceSets { … { dependencies { … } } } }` is counted) — so an unknown head is over-marked ("may be incomplete"), never silently lost, which is the record's title ("a block the index cannot evaluate is marked") applied without a gap. - A receiver-qualified head (`<expr>.dependencies {`) is never DIRECT — the index does not resolve receivers — and is counted. Today's word tokenizer mines `subproject.dependencies {` as a plain block; no receiver-qualified head sits at a script's top level or directly under a scope head in the three corpora (measured), so no declared set moves. It makes kafka's count 1 (`build.gradle:518`, under `subprojects {` › `afterEvaluate { subproject ->` › `if (hasMockitoCore) {`), as the record's rule ("blocks skipped under a condition or callback") and RG-REQ-002-L11 require; the record's kafka field literal is 1 by its dated "Correction 2026-09-24" (D-DGC-QUALIFIED-HEAD = A; the rejected option B, treating a receiver-qualified head as no `dependencies` block at all, would have dropped a declaration site silently).

The shape `{count, first}` and both envelope keys are the record's, unchanged.

### 2.2 Evidence taxonomy (L13's verification criterion → test)
- `buildscript { dependencies { classpath … } }` beside a real block yields only the real block → `gradle_buildscript_dependencies_are_never_declared`, `gradle_plugin_management_dependencies_are_never_declared`; field: kafka :27, grpc-java core :3, gae-jdk8 :18 (DGC-A04).
- A root top-level block reaches the root project only → `gradle_top_level_block_is_the_scripts_own_scope`, `gradle_root_top_level_block_never_reaches_a_subproject`.
- `allprojects` reaches every project, `subprojects` every non-root project → `gradle_allprojects_block_is_recorded_in_the_allprojects_scope`, `gradle_subprojects_block_is_recorded_in_the_subprojects_scope`, `gradle_allprojects_reaches_every_project_and_subprojects_every_non_root_project`; the changed expectation of `gradle_nested_subprojects_block`.
- `project(':a') { dependencies { } }` is attributed to `a` only, the Gradle path mapped through the settings file → `gradle_project_block_is_recorded_under_its_gradle_path`, `gradle_project_without_its_own_script_declares_only_its_root_project_block`, `gradle_project_path_follows_the_settings_projectdir_relocation`.
- Attribution is per project, never per shared script → `gradle_projects_sharing_one_script_resolve_independently_of_order`.
- Scope blocks of intermediate project scripts reach their descendants (allprojects: itself and descendants; subprojects: descendants; `project(…)` blocks from any script of the build, absolute or relative) → `gradle_intermediate_project_scope_blocks_reach_their_descendants` (review-0 F-DGC-01).
