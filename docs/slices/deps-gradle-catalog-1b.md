## 2. Contract
### 2.1 The fix, at the cause
1. **Alias mining** (`config.rs`: `ScopeSets::mine` at :549, beside `extract_gradle_coordinates` :802). An accessor token `libs.<alias>` or `libraries.<alias>` is an ALIAS REFERENCE in the scope of its DIRECT `dependencies` block only when it stands in a configuration argument position:
   - outside every string literal (comments are stripped first, as today);
   - at the block's own brace depth, never inside a closure nested in it (`implementation(libs.a) { because(libs.x) }`: `libs.x` is not a declaration);
   - in the argument list of the statement's leading word — the configuration verb, any verb, as the coordinate miner is verb-agnostic — unparenthesised (`implementation libs.a, libs.b`), inside the verb's own parentheses (`implementation(libs.a)`, `api (libs.a)`), or inside `platform(…)` / `enforcedPlatform(…)` there;
   - on the statement's line or on a continuation line: a line is a continuation when the statement's previous line ends with `,` or an argument parenthesis is still open (grpc-java `core/build.gradle:23-24` `implementation libraries.gson,` / `libraries.android.annotations,`).

   A token inside any other call's parentheses (`because(libs.x)`, `files(libs.x)`), in a statement that assigns (`=` at its top level), or that is itself the statement's leading word is not a declaration. The coordinate miner is unchanged: it still reads every quoted coordinate anywhere on an in-block line. The alias text may be dotted. `GradleScriptScopes` carries alias references beside groups, per scope, with the line of each reference. Counted (undetermined) blocks are not mined, as today. A script, or a `project('<p>')` block, whose only facts are alias references is no longer empty: the emptiness rule (`GradleScriptScopes::is_empty` :508-517, applied at :794-796; documented at :671-672) and the `projects` presence filter (:786-789; documented at :498) count alias references. `gradle_non_literal_forms_not_fabricated` is renamed `gradle_non_literal_forms_other_than_catalog_aliases_are_not_fabricated`.
2. **Catalogs**. The reader lives in a new crate-private module `rust/crates/repo-index/src/gradle_catalog.rs`, declared in `repo-index/src/lib.rs`. Catalog reading is a new responsibility, and config.rs (3,204 lines) and manifest_deps.rs (2,528 lines) are over the 500-line guardrail. `manifest_deps.rs` resolves references at the build: `GradleBuild::declared_for` :708 composes scopes, and there is one catalog per build. The build's directory is its settings directory, or the script's directory for a single-script build. The sources:
   - (a) TOML: `<build dir>/gradle/libs.versions.toml`, read with the `toml` crate (D-DGC1B-TOML-1). A `[libraries]` entry whose value is a string `"group:artifact[:version]"`, or a table with `module = "group:artifact"`, maps alias → group.
   - (b) Groovy: every script the ROOT project script applies by `apply from: "<path>"`, `apply from: file('<path>')` or `apply from: "$rootDir/<path>"` at its top level or inside `buildscript { }`. 1A's `buildscript` exclusion is about `dependencies` blocks, not `apply from:`; kafka's map is applied at `build.gradle:23` inside `buildscript`. Each such script is read once for `libs = [ … ]` / `libs += [ … ]` map literals whose entries are `alias: "<group>:<artifact>[:…]"`. ALIAS-MAP ENTRY RULE (D-DGC1B-ARTIFACT-INTERPOLATION-1): an entry binds its alias to `<group>` when `<group>`, the text before the first `:`, passes the coordinate-segment test `is_coordinate_segment` (config.rs:838: non-empty, only ASCII alphanumerics, `.`, `-`, `_`) and the artifact text after it is non-empty. Interpolation in the artifact or the version plays no part: kafka `gradle/dependencies.gradle:235` `scalaLogging: "com.typesafe.scala-logging:scala-logging_$versions.baseScala:$versions.scalaLogging",` binds `libs.scalaLogging` (`build.gradle:1109`) to `com.typesafe.scala-logging`. An entry whose group fails the test (a `$` interpolation in the group), or whose value has no `:`, is not a catalog entry; a reference to its key is counted `no catalog entry`. The 1A literal-coordinate reader `coordinate_group` (config.rs:825, which tests both segments) is unchanged. An `apply from:` enclosed by any other block (`if (…)`, `else`, `afterEvaluate`, `allprojects`, any closure) is NOT followed: the index cannot establish that it runs. An `apply from:` in a non-root project script is not a catalog source (a stated limit).
   - (c) The statement `libraries = libs` in a project script of the build (grpc-java `build.gradle:159`) makes `libraries.` resolve through `libs`. Without it, a `libraries.` reference resolves to nothing.

   The alias key is compared after `-`/`_` → `.` (Gradle's accessor rule). ONE BINDING RULE: a reference binds to a group only when every catalog source of its build was read and exactly one group answers its accessor. A bound reference joins the declared set of its scope. Every other reference is COUNTED on the build's record (`unresolved_alias_refs {count, first}`) and never becomes a group guessed from the alias text:
   - no source of the build answers the accessor;
   - a source of the build could not be read: a TOML catalog that fails to parse or cannot be read, or an applied script that cannot be read (missing, outside the repository, or named by an argument that is not a literal path) — every alias reference of the build counts and none binds;
   - a source of the build was not read: an `apply from:` inside a block other than `buildscript` — every alias reference of the build counts and none binds;
   - two catalog keys normalise to the reference's accessor with different groups — that reference binds to neither.

   `first` is the build's first counted site by path, then line, and states the predicate that failed for it (section 2.2). This one rule replaces a list of cases: a reference is certain only when the whole catalog of its build is known and answers it once.
