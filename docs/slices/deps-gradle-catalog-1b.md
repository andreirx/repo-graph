## 2. Contract
### 2.1 The fix, at the cause
1. **Alias mining** (`config.rs`: `ScopeSets::mine` at :549, beside `extract_gradle_coordinates` :802). An accessor token `libs.<alias>` or `libraries.<alias>` is an ALIAS REFERENCE in the scope of its DIRECT `dependencies` block only when it stands in a configuration argument position:
   - outside every string literal (comments are stripped first, as today);
   - at the block's own brace depth, never inside a closure nested in it (`implementation(libs.a) { because(libs.x) }`: `libs.x` is not a declaration);
   - in the argument list of the statement's leading word — the configuration verb, any verb, as the coordinate miner is verb-agnostic — unparenthesised (`implementation libs.a, libs.b`), inside the verb's own parentheses (`implementation(libs.a)`, `api (libs.a)`), or inside `platform(…)` / `enforcedPlatform(…)` there;
   - on the statement's line or on a continuation line: a line is a continuation when the statement's previous line ends with `,` or an argument parenthesis is still open (grpc-java `core/build.gradle:23-24` `implementation libraries.gson,` / `libraries.android.annotations,`).

   A token inside any other call's parentheses (`because(libs.x)`, `files(libs.x)`), in a statement that assigns (`=` at its top level), or that is itself the statement's leading word is not a declaration. The coordinate miner is unchanged: it still reads every quoted coordinate anywhere on an in-block line. The alias text may be dotted. `GradleScriptScopes` carries alias references beside groups, per scope, with the line of each reference. Counted (undetermined) blocks are not mined, as today. A script, or a `project('<p>')` block, whose only facts are alias references is no longer empty: the emptiness rule (`GradleScriptScopes::is_empty` :508-517, applied at :794-796; documented at :671-672) and the `projects` presence filter (:786-789; documented at :498) count alias references. `gradle_non_literal_forms_not_fabricated` is renamed `gradle_non_literal_forms_other_than_catalog_aliases_are_not_fabricated`.
2. **Catalogs**. The reader lives in a new crate-private module `rust/crates/repo-index/src/gradle_catalog.rs`, declared in `repo-index/src/lib.rs`. Catalog reading is a new responsibility, and config.rs (3,204 lines) and manifest_deps.rs (2,528 lines) are over the 500-line guardrail. `manifest_deps.rs` resolves references at the build: `GradleBuild::declared_for` :708 composes scopes, and there is one catalog per build. The build's directory is its settings directory, or the script's directory for a single-script build. The sources:
   - (a) TOML: `<build dir>/gradle/libs.versions.toml`, read with the `toml` crate (D-DGC1B-TOML-1). A `[libraries]` entry whose value is a string `"group:artifact[:version]"`, or a table with `module = "group:artifact"`, maps alias → group.
   - (b) Groovy: every script named by an `apply from: "<path>"`, `apply from: file('<path>')` or `apply from: "$rootDir/<path>"` statement of the build's scripts. Its map is a source for the projects the statement applies to (item (d)). 1A's `buildscript` exclusion is about `dependencies` blocks, not `apply from:`; kafka's map is applied at `build.gradle:23` inside the root `buildscript` and reaches the whole build. Each such script is read once for `libs = [ … ]` / `libs += [ … ]` map literals whose entries are `alias: "<group>:<artifact>[:…]"`. ALIAS-MAP ENTRY RULE (D-DGC1B-ARTIFACT-INTERPOLATION-1): an entry binds its alias to `<group>` when `<group>`, the text before the first `:`, passes the coordinate-segment test `is_coordinate_segment` (config.rs:838: non-empty, only ASCII alphanumerics, `.`, `-`, `_`) and the artifact text after it is non-empty. Interpolation in the artifact or the version plays no part: kafka `gradle/dependencies.gradle:235` `scalaLogging: "com.typesafe.scala-logging:scala-logging_$versions.baseScala:$versions.scalaLogging",` binds `libs.scalaLogging` (`build.gradle:1109`) to `com.typesafe.scala-logging`. An entry whose group fails the test (a `$` interpolation in the group), or whose value has no `:`, is not a catalog entry; a reference to its key is counted `no catalog entry`.
