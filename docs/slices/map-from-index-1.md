# MAP-FROM-INDEX-1 — deterministic MAP.md from the index; the LLM leaves the structure path

Status: SPECIFIED (2026-07-15, operator-ratified: rmap-native renderer; queued after
ATTRIBUTION-1, BEFORE v0.7.0) · Track: Discovery core / vision enforcement
Origin: operator field finding (2026-07-15): rgistr's local-LLM backend (gemma4) produces
"somewhat bad" MAP.md structure, while the same information is derivable deterministically —
another indexer proved it without any model call. VISION commitment #1 ("facts computed
from source, reproducible, NEVER model output") makes the LLM structure path a standing
violation: `rmap index` already extracts per file the symbols (with signatures), imports,
call edges, complexity, and module/package membership a MAP.md needs.

## 1. Contract

1. **`rmap map` subcommand (RATIFIED renderer).** Renders MAP.md files from the current
   READY snapshot's facts — no LLM anywhere in the path. Deterministic: same snapshot →
   byte-identical output (stable ordering everywhere).
2. **Placement + lifecycle mirror rgistr's shipped conventions** (inventory them first:
   per-dir and per-file `*_MAP.md` placement, the do-not-hand-edit marker comment, any
   read-side tolerance contracts in rgistr's readMap). The marker becomes
   `<!-- generated by rmap map from snapshot <short-uid>; do not hand-edit -->` — carrying
   provenance the old header lacked (and no token-waster frontmatter — that stripping is
   ratified and shipped).
3. **Content = extracted facts, reader-frame:** per file — symbols with signatures
   (functions/classes/methods/enums), imports (resolved target where known), complexity
   where measured (coverage-honest per METRIC-LANG-COVERAGE); per directory — the file
   inventory + package-group/module identity + intra-directory dependency sketch from
   import/call edges. Layer labels follow the certainty model (extracted facts only; no
   inferred prose). What the index does not know, the map does not say.
4. **Honest coverage:** files the index skipped (size caps, unsupported language) are
   LISTED as unmapped with the reason — the map never silently omits a file that exists.
5. **rgistr:** its LLM structure path is superseded; this slice adds a deprecation note to
   rgistr's README pointing at `rmap map` (full TS retirement stays TS-PROTOTYPE-
   RETIREMENT-1's job). rgistr itself is NOT modified beyond the note.

## 2. Stop conditions

- Read/render only: no daemon write paths, no schema changes, no extractor changes. The
  renderer consumes existing reads (agent-port or storage read paths; inventory first,
  additive port reads allowed per the RR1_BOUNDARY precedent — record).
- Do NOT delete or rewrite rgistr (the note only). Do NOT commit.
- If the index lacks a fact class rgistr's maps materially depended on (inventory will
  tell) → STOP + DECISION_REQUIRED, never fabricate.

## 3. Validation (SYNCHRONOUS; INCREMENTAL REPORT — binding, per the ATTRIBUTION-1 packet)

- Cargo gates from `rust/` (build / full UNEXCLUDED workspace suite / fmt / clippy), raw
  exit statuses as they land.
- Named tests: byte-determinism (render twice, identical); marker + provenance present;
  unmapped-file honesty; stable ordering under permuted input; a fixture crate's MAP.md
  golden test.
- Isolated live dogfood (/private/tmp + stdio; registry checksum before/after): index
  repo-graph, `rmap map` a chosen crate + a TS directory, inline the RAW generated MAP.md
  files; run twice → diff empty (determinism live). Compare side-by-side with the
  rgistr-generated MAP.md for the same directory (inline both; the delta narrative is the
  usefulness evidence).

## 4. Definition of done

`rmap map` produces deterministic, provenance-marked, coverage-honest MAP.md from the
index for Rust and TS directories; live proof includes the rgistr comparison; rgistr
README carries the deprecation note; no model call anywhere in the map path.
