# D-HSP-SCOPE-1 — `--help` lists every dispatched command with the handler's own usage line, enforced by a parity test; the `risk` coverage hint (RISK-CURSOR-1) is the same defect class and is fixed in the same slice

Raised: 2026-10-04 by the manager packeting round-eight queue item 9 (RC-5, `docs/audits/2026-10-03-root-causes-v0.20.0.md`).

**The problem in plain words.** `rmap --help` is a hand-written list (`rgr/src/cli/usage.rs:50-162`). It drifted from the dispatcher (`rgr/src/main.rs:84`, 44 commands): nine commands are not listed at all — among them the user commands `deps`, `enrich`, `inferences`, `contracts` — and the three `declare` lines show a "resolve repo from cwd" form while the handlers require `<db_path> <repo_uid>` first (`rmap declare quality-policy <policy_id> …` in help; `usage: rmap declare quality-policy <db_path> <repo_uid> <policy_id> …` from the handler). An agent that follows the help text gets a usage error; an agent that reads the help does not learn that `deps` or `enrich` exist. The `risk` zero-state hint `Import coverage data with 'rmap coverage <db> <repo> <report>'` (`presentation/risk.rs:118`) is the same class — a hand-written command string that no longer matches its handler (`rmap coverage <report> [--json]`, `coverage_cmd.rs:41`) — recorded as RISK-CURSOR-1 (RG-REQ-012-L03).

**Options (reward / risk, by usefulness to an agent net of misdirection).**
- A — one slice: help lists every dispatched command (`dev` named as developer-only, `daemon` as the deprecated shim for `rmapd`, `dead` as disabled per its contract — no command is hidden, because a hidden command's usage error is the first thing an agent would see), the `declare` lines are the handlers' own usage constants, and a unit test derives the dispatcher's arms from `main.rs` and asserts each appears in the help text, so the list cannot drift again; the `risk` hint is fixed to the handler's usage in the same change. Reward: `--help` becomes a true map of the surface; the parity test keeps it so. Risk: `--help` grows by nine lines; `dev`/`perf`/`metrics` appear with an explicit "developer and diagnostics" label.
- B — fix only the three `declare` lines and the hint (no parity test, no missing commands). Reward: the recorded drift closes. Risk: the next command added drifts the same way; RG-REQ-012-L09's "automated check — none exists" stays open.
- C — generate help from a command table that the dispatcher also uses (one source). Reward: drift impossible by construction. Risk: a refactor of `main.rs`'s match into a table touches every command's entry; larger review for the same user-visible outcome; the parity test gives the same guarantee at far lower cost.

Resolved: 2026-10-04 by the OPERATOR (in-place manager) as **A**; the human may override (C is the structural alternative if a command table is wanted later). Candidate paths: `rgr/src/cli/usage.rs`, `rgr/src/commands/declare/{boundary,requirement,quality_policy}.rs` (usage constants made crate-visible), `rgr/src/presentation/risk.rs`, `docs/cli/rmap-contracts.md`. `main.rs` is read by the test (`include_str!`) and not changed.

## What this record rules
- Help lists every string arm of the dispatcher's command match, grouped by workflow role (RG-REQ-012-L09); the three `declare` lines and the `coverage` line are the handlers' usage strings; `dev`, `perf`, `metrics` sit under "Developer and diagnostics", `daemon` and `dead` under "Deprecated and disabled" with their status words.
- A unit test derives the arm list from `main.rs` text and fails when any arm is missing from `usage_text()`; a second test asserts each `declare` help line equals its handler's constant and the `risk` hint equals the `coverage` handler's usage head.
- RISK-CURSOR-1 closes here; no other printed command string is changed (TRUST-CEILING-WORDING-1 and the other round-eight items stay separate).
