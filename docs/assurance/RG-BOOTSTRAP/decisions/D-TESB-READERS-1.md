## 1. Two axes, two scopes (D-TESB-01 = A)
- **Resolution class — every IMPORTS reader.** Every consumer that reads IMPORTS rows (module derivation, cycles, path, map, boundary, trust, orient, explain's Import-cycles block, `imports <file>`, LiveGraph feed, governance gate, cycle audit) reads static/dynamic by default, admits inferred rows only under `--include-inferred`, and states the inferred remainder as a count with the flag (RG-REQ-002-L11). This is the gate D-PSI-RELEASE-GATE-1 exists for: a newly inferred import edge must be read as certain nowhere.
- **Test status — the module-architecture surfaces L12 names.** `modules list`, `modules deps`, `cycles`, `orient` and `explain`'s Import-cycles block default to production imports with `--include-tests` and the stated remainder. A per-file answer (`imports <file>`, `explain <file>`'s own imports) keeps every import of that file whatever its `is_test` — the file is the subject; `path` walks certain hops of either status and states nothing about test status (its subject is reachability, not architecture); governance readers (`gate`, `modules violations` renderers) keep their ratified populations unchanged and partition only by resolution. Reward: no surface hides a fact about its own subject; frozen verdicts stay frozen; the inferred axis is closed everywhere. Risk: the sentence "every IMPORTS reader" in D-PSI-RELEASE-GATE-1 is read as the resolution axis only — this record is the reading.
Rejected: B (literal every-reader test default: hides a test file's imports from `imports <file>`; changes governance verdicts without a ratification); C (narrow scoping with inline inferred rows: L11 unmet on the readers left out).
