## The problem, as put to the human

`rmap find "where are conversations persisted to disk"` on FRAKTAG does not show `ConversationManager.createSession` (packages/engine/src/core/ConversationManager.ts:71) or `logTurn` (:133): their embedded text (name + own doc + body) contains no "persist"/"disk"/"store"; they score 0.274 / 0.155 under the 0.30 floor. L10 was ratified as a diagnosis (SEED-CHUNK-3 §2.6), never measured.

## Measured (FRAKTAG persistence query; grpc-java two task queries; leveldb crash recovery; controls)

- The enclosing type's doc alone lifts createSession 0.274 → 0.333 (first sentence, ≤ 160 chars) … 0.372 (whole doc), into the top ten above the unchanged floor.
- The identifier summary never raises a target; it lowers createSession by 0.016 and listSessions by 0.023 (potion's tokenizer already splits identifiers; the summary only re-weights the mean).
- The whole class doc pulls precise matches away (`AbstractStub.withDeadline` rank 2 → 9 on "how is the deadline propagated to the server") and turns short members into class-doc echoes (a two-line `logger` field at rank 1; a five-line constructor in FRAKTAG's top four); the owning class drops from rank 3 to 5.
- The first sentence keeps the FRAKTAG gain with the least harm (owning class rank 3; `withDeadline` rank 2; echo rows low).
- No variant lifts logTurn over the floor (best 0.224); leveldb is unchanged (C++ class docs are not captured as `doc_comment` on the class node — a separate extractor fact); every variant re-embeds every repo once, silently.

## Options (reward / risk)

- First sentence only (RECOMMENDED; chosen): drop the summary from L10; createSession 0.333 rank ~9, owning class rank 3, `withDeadline` rank 2, smallest code (one bounded helper). Risk: thin margin (0.033), logTurn stays invisible, one grpc row slips (ClientStream.setDeadline 4 → 9), one-time silent re-embed.
- Whole class doc: createSession 0.370 rank 6, retry schedulers up. Risk: the measured dilution and echo rows; breaks SEED-CHUNK-3's accepted outcome (owning class rank 3 → 5).
- As ratified, with summary: no requirement edit. Risk: a clause kept alive against its own evidence; a splitter, a bound and tests for no reader benefit; −0.016 on the target.
- Withdraw the slice: no re-embed, no dilution. Risk: task queries keep missing the working method whenever its own text lacks the query's words; L10 stays unmet.

## Resolution

RG-REQ-010-L10 now requires "the FIRST SENTENCE of its enclosing type's doc comment under a named character bound (no identifier summary — measured to be harmful)"; the criterion states the measured before table and the outward after. Carried by RG-BOOTSTRAP-INPUT-6 (standalone review + operator approval 6, same commit). The bound is the slice-owned constant `repo-graph-seed::document::MAX_ENCLOSING_SENTENCE_CHARS` (160 at ratification), named in L10 with its value stated as the slice's, not frozen by the requirement.
