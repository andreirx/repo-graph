Raised: 2026-10-03 by the document review of TS-ALIAS-RESOLUTION-1 INPUT-1 (reviewer codex gpt-6-sol).

**The problem in plain words.** `resolve_tsconfig_alias` (`repo-graph-import-resolver/src/lib.rs:425`) returns `Ambiguous` without the candidate set (`:388`), and the indexer's `TargetResolution::Ambiguous(_)` would have nothing to record — yet RG-REQ-002-L11 requires every candidate recorded, never a pick. The config type `TsconfigAliasConfig` lives in `repo-graph-ir` and is not re-exported, so naming it from the indexer would need a second crate edge the human did not rule.

B/C — shapes that add an `indexer → repo-graph-ir` edge: an unruled boundary. Deferral — ambiguous candidates stay unavailable.

Resolved: 2026-10-03 by the OPERATOR (in-place manager) as **A**, overridable by the human; recorded with D-TSA-SCOPE-1.

## Correction 2026-10-03 (operator; references the option A text above and the INPUT-2 document review's D-TSA2-RECORDS)
The clause "`resolve_tsconfig_alias` becomes a fold over it" is SUPERSEDED. The document review of INPUT-1 (F-TSA-01) showed the LiveGraph function unions every matching pattern while `tsconfig_alias_hits` follows TypeScript's selection (exact pattern first; otherwise the matching wildcard with the longest prefix; a tie binds nothing). Folding the LiveGraph function over the new one would change its accepted behaviour on the LiveGraph route inside a slice that preserves it. What stands: `tsconfig_alias_hits` is added beside `resolve_tsconfig_alias`, reuses `match_alias_pattern` and `candidate_paths` (one pattern grammar, one extension list — D-TSA-RESOLVER-EDGE-1's "one matcher"), and `resolve_tsconfig_alias`, its tests and its caller stay byte-identical. The selection difference between the two routes is the filed follow-up ALIAS-SELECTION-PARITY-1, not this slice's scope.

## Correction 2026-10-03 (operator; references option A's signature above and the INPUT-6 document review's D-TSA6-RETURN-SHAPE; the author's O-TSA6-01)
The return shape `Option<BTreeSet<String>>` is SUPERSEDED. The INPUT-6 review (F-1) showed that two wildcard patterns tied for the longest prefix would return `Some(∅)` and drop the files the tied patterns reach — known candidates removed from the agent-facing row, which RG-REQ-002-L11 forbids; and `Option<set>` cannot tell a one-candidate tie from a selected one-candidate binding. The one additive function now returns `pub enum TsconfigAliasHits { NoPatternMatches, SelectedPattern(BTreeSet<String>), TiedPatterns(BTreeSet<String>) }` — each variant named after its value; a tie still binds nothing and carries the union of the tied patterns' deciding-substitution hits as candidates under the ambiguous basis `tied_tsconfig_paths_patterns` (storage `AMBIGUOUS_BASES`, an allocated path). Everything else in option A stands: one additive matcher on the import-resolver crate, one pattern grammar, one candidate list, `resolve_tsconfig_alias` and the LiveGraph route byte-identical, no new crate edge. Axis recorded: the variants are fixed (three outcomes of TypeScript's selection) and the operations over them grow (indexer stage today) — a sum type with exhaustive matches, so a fourth outcome breaks every consumer deliberately.
