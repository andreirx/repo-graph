# D-DGC1B-ALIAS-MARKING-1 — an alias reference that resolves to no catalog entry is counted on the build's provenance record and stated once in `deps list`, never guessed and never dropped

Raised: 2026-10-03 by the manager while packeting DEPS-GRADLE-CATALOG-1B (RG-REQ-002-L11; the D-DGC-CONDITIONAL-1 precedent for undetermined blocks).

**The problem in plain words.** A dependency line `implementation libs.foo` whose alias `foo` is defined in no catalog the reader found (no `gradle/libs.versions.toml` in the settings directory, no `libs += [ … ]` map in a script the root applies, a catalog that failed to parse, an alias renamed through a form the reader does not follow) declares something the index cannot name. Today such lines read as nothing and the row says `undeclared N` with no hint. MEASURED: kafka's 103 distinct `libs.` aliases and grpc-java's 70 `libraries.` aliases all resolve, so the corpus exercises the resolved path; the marking exists for the repositories we have not seen.

**Options (reward / risk, by usefulness to an agent).**
- A — mirror the undetermined-blocks marking: the build's `ManifestRecord`/`ManifestProvenance` gains `unresolved_alias_refs: Option<{count, first: "<path>:<line> <accessor>"}>` (absent when zero; serialized only when present; a malformed value fails the whole `deps_manifests` decode → the existing unknown-with-reason path); the envelope gains `declared_unresolved_alias_refs` and `declared_unresolved_alias_note`, summed over tracked provenance; the human output prints one line after the undetermined-blocks line: `declared set may be incomplete: N alias reference(s) resolve to no catalog entry (<path>:<line> libs.foo) — investigate`. Reward: the agent reads every `undeclared` count below as possibly an alias the index could not resolve, with the first site to open. Risk: two additive wire keys and one record field (the 1A shape, second instance).
- B — count only (no first site). Risk: the agent knows something is missing and not where.
- C — resolve to nothing silently (today). Risk: `undeclared` reads as a certain absence.

Resolved: 2026-10-03 by the OPERATOR (in-place manager) as **A**; overridable by the human. The phrase restates the predicate at `resolve_alias_refs` (the alias lookup returned no entry), in the reader's words.

## Correction 2026-10-03 (operator; references option A above and the DEPS-GRADLE-CATALOG-1B document review's D-DGC1B-PHRASE, option A)
The phrase "resolve to no catalog entry" is SUPERSEDED: it is false when the catalog could not be read or parsed (no entry was tested). The line becomes `declared set may be incomplete: {N} alias reference(s) could not be resolved ({first}) — investigate`, and `{first}` states the predicate of the first site: `{path}:{line} {accessor}: no catalog entry` when the lookup found no entry, or `{path}:{line} {accessor}: catalog {catalog path} could not be read ({error})` when the build's catalog failed to read or parse (every alias reference of that build is counted under that reason). The record field keeps the shape `unresolved_alias_refs {count, first}`; the reason lives in `first`'s text, so a build with both kinds states its first site's reason and its total count. Tests assert both `first` forms end to end.
