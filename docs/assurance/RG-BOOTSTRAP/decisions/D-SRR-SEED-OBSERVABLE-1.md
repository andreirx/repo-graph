# D-SRR-SEED-OBSERVABLE-1 — the valid-root seed hand-off is proven through a test-only observer of the root the pass's lookup returns, before any model load

Raised: 2026-10-05 by the INPUT-2 document review of STATE-ROOT-RELATIVE-REPO-ROOT-1 (author claude-opus-5-5 F-PREP-01, reviewer codex gpt-6.1-sol F-SRR-PREP-15; both DECISION_REQUIRED SRR-SEED-ROOT-OBSERVABLE, both recommending A).

**The problem in plain words.** INPUT-2 asks a test to observe that refresh hands the registry root to the seed pass and that the pass reads the working tree there. The seed pass reads the working tree only after it loads its embedding model (`daemon-runtime/src/seed_pass.rs:455-458` loads, `:502-516` reads — verified), and the model loader fetches missing files from the network into `<state root>/seed-model-cache` (`seed/local_engine.rs:205-236`; no offline switch). In a test's fresh `tempfile` state root the test either downloads a model (not hermetic, outside the isolated-proof rules) or skips before the read it must observe.

**Options (reward / risk).**
- A — a test-only observer in `daemon-runtime/src/repo_root.rs` records the root the store-keyed lookup returns to each pass, following the existing precedents `set_test_registry_builder` and `set_auto_seed_for_test`; the seed pass resolves its root BEFORE loading the model, and under the observer the test ends the pass right after the lookup, so no model is loaded and nothing is fetched. Reward: hermetic; it fails for the wrong root; the hand-off is executed, not inferred. Risk: the subsequent working-tree read is verified by inspection, not executed — the oracle states that limit.
- B — supply pinned model files in each isolated cache and run offline. Reward: executes the real read. Risk: model files become a test input and a cache-layout prerequisite; slow.
- C — drop the valid-root seed proof. Reward: no code. Risk: that part of RG-REQ-011-L13 has no executed proof; it would be a recorded residual.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A** — the recommendation of both reviews; the human may override. Abstraction ledger: what — a `#[doc(hidden)]` test hook in `repo_root.rs` (record the root per pass; optionally end the pass after the lookup); concrete current user — `refresh_hands_the_registry_root_to_enrich_and_seed`; axis — a test seam unobtainable more simply (the read sits behind a network model load); rejected simpler alternative — observing the registry lookup alone without the pass (it would not prove the pass received that root). The enrich half is observed through the existing resolver seam. SRR-C04 inspects that the root the seed pass receives is the one its working-tree read uses (`seed_pass.rs:502-516`).

**Correction 1 (2026-10-05, operator; appended — the text above is not rewritten; decision A unchanged).** The INPUT-2 cycle-5 review (author F-PREP-04/05/06, reviewer F-SRR-PREP-17) showed that "an observer in `repo_root.rs` records the root the store-keyed lookup returns to each pass" can be read as an observer INSIDE the shared lookup — which takes `(state, db_path, repo_uid)`, names no caller, and is called first by the enrich pass with the same arguments: such a record exists whether or not the seed pass ever asks for the root, and an early end there would also stop enrich before its resolver seam. The rule, restated: (1) the SEED PASS's call site, right after its own successful registry lookup, passes the root it received to the `#[doc(hidden)]` hook in `repo_root.rs`, which records it as the seed pass's root and answers whether to end; (2) the test requires a seed-attributed record for its repository equal to the registry root — an absent or different record fails; (3) only the seed call site applies the early end, with the existing `SeedAttempt::Superseded` outcome (no new log phrase); the shared lookup and the enrich path are unaffected; (4) the seed pass's lookup and the hook come BEFORE `LocalEmbedder::load` — an obligation on the candidate, not a property of HEAD, where the root is `Path::new(repo_display)` at `seed_pass.rs:503`, after the load at `:455`; (5) inspection confirms the seed pass's working-tree read uses that same root.
