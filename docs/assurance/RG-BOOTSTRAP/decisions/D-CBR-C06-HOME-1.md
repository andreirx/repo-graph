# D-CBR-C06-HOME-1 — operator decision (2026-09-14)

Raised by: the claude-opus-4-8 builder of CALL-BINDING-RECEIVER-1 (third admission, cycle 2, under INPUT-4) after the codex gpt-5.6-terra reviewer's finding F-CBR-003 (the CBR-C06 "integration test" was a resolver-only mock reported as passed).

Question: CBR-C06 requires a test that writes the A/B/X C++ fixture into a temporary directory, indexes it, and asserts callers/callees and the receiver self-loop invariant on the resulting store. The builder established that such a test cannot live in `rust/crates/indexer/tests/` — the indexer crate has no dependency on the C++ extractor or the storage crate, and `tests/parity.rs` exercises JSON policy fixtures, not indexing. It STOPPED rather than mock again, and raised: A re-home the test to `repo-graph-repo-index`'s integration harness (which depends on cpp-extractor, indexer, storage and tempfile, and already indexes fixtures — `cpp_sb_1_integration.rs`, `index_*_fixture_*`); B accept the resolver-seam test plus the live leveldb proofs as the seam evidence; C leave C06 failed. It also reported CBR-C01 failing only because the mandated malformed-metadata regression test makes the `receiver_binding_` family six, not the oracle's literal five.

Decision: **A, plus the C01 count.** The live leveldb proofs (C10–C15) show the extractor→index→resolver seam on real data, but they are operator-time proofs, not tests: without a fixture test in `cargo test`, nothing in the suite would catch a future divergence between the extractor's `receiverType` shape and the resolver's reader — the whack-a-mole the requirements exist to prevent. CBR-C06 is re-homed to `rust/crates/repo-index/tests/call_binding_receiver.rs` (command `cargo test -p repo-graph-repo-index --test call_binding_receiver`), which becomes a candidate path; the indexer's `tests/call_binding_receiver.rs` stays as the honest resolver-seam unit test it now is. CBR-C01 expects six `receiver_binding_` tests (the sixth: `receiver_binding_malformed_metadata_stays_unresolved`, the F-CBR-004 regression). B is rejected (no permanent seam guard); C is rejected (a failing mandatory check ships nothing).

Consequence: oracle correction OC-4 (C06 command/expected + candidatePaths; C01 count) → baseline INPUT-5; the cycle-2 candidate (F-CBR-004 fix with the `ReceiverDisposition {Receiverless, ExplicitThis, Indirect, Unreadable}` sum type; six tests; honest seam test) is re-admitted and the builder writes the repo-index fixture test.
