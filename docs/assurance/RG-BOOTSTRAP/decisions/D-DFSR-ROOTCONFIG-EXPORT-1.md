# D-DFSR-ROOTCONFIG-EXPORT-1 — the `platform/mod.rs` re-export list names only what production code outside the child module uses; `RootConfig` is re-exported `#[cfg(test)]`

Raised: 2026-10-05 by the implementation reviewer of DOCTOR-FALLBACK-STATE-ROOT-1 (admission 1, cycle 1; the reviewer's label DFSR-D01 — not the slice document's "DFSR-D01" daemon-identity option, which is unrelated) after the builder recorded the deviation in `build-progress.md`.

**The problem in plain words.** The accepted slice document's BINDING SEAM (INPUT-1, DFSR-C01 inputs) told the builder to write one production re-export line in `platform/mod.rs`: `pub(crate) use doctor_config_probes::{doctor_config, early_config_probes, service_note_applies, DoctorConfig, RootConfig};`. No production code outside the child module ever names `RootConfig`: `execute_doctor` and the macOS adapter get a `DoctorConfig` from `doctor_config()` and ask the two predicates; only the sibling unit tests in `platform/macos.rs` and `commands/doctor/summary.rs` construct `RootConfig::Global` values. An unconditional re-export is therefore an unused import in the non-test build, and the slice's own gate DFSR-C02 (`cargo clippy --all-targets -- -D warnings`) fails on it (builder-executed, macOS). The seam asked for something the code does not need; the document, not the code, was wrong.

**Options (reward / risk).**
- A — amend the seam: the production re-export list is `{doctor_config, early_config_probes, service_note_applies, DoctorConfig}`; `RootConfig` is re-exported on its own `#[cfg(test)] pub(crate) use …;` line; `service_note_detail` keeps its own macOS-gated line. Reward: the re-export list states the real users; the build is warning-free without a lint allowance; no runtime change. Risk: the slice document must be amended (a new baseline INPUT-2, one document review, re-admission); a later production caller imports the type deliberately.
- B — keep the literal seam with `#[allow(unused_imports)]` or an artificial production use. Reward: no document amendment. Risk: a lint allowance that exists only to satisfy a wrong sentence; a false shape the next reader must explain.
- C — defer acceptance. Risk: the isolated-stdio `doctor` defect stays.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A**; the human may override. The seam sentence in the slice document is amended for INPUT-2; DFSR-C04 (1) judges the amended seam. The builder's explicit binding `let cfg: DoctorConfig = doctor_config();` in `execute_doctor` (which keeps the `DoctorConfig` re-export used on Linux, where `macos.rs` is not compiled) is within the seam and is accepted as written.
