# D-SRR-SCOPE-1 — every working-tree reader takes the repository root from the registry, passed explicitly; an unreachable root is named, never shown as an absence

Raised: 2026-10-05 by the operator (in-place manager) while specifying STATE-ROOT-RELATIVE-REPO-ROOT-1 from audit round nine's RC-1 (`docs/audits/2026-10-05-root-causes-v0.21.0.md`), after the human's D-SRR-ROOTPATH-1 A and the human's ruling to fix this defect first (2026-10-05).

**The problem in plain words.** The daemon finds a repository's working tree at ELEVEN places by joining the store's relative `repos.root_path` onto the store file's directory: refresh (`daemon-runtime/src/dispatch.rs:3510`, which also hands that path to the auto-enrich and seed passes and re-stamps the field), docs list (`:5749`), docs extract (`:5879`), the drift probe used by orient, check and explain (`:4294` via `handlers/quality/support.rs:19`), churn, hotspots, risk and coverage (`handlers/quality/{churn.rs:100, hotspots.rs:110, risk.rs:99, coverage.rs:130}`), map (`handlers/map.rs:113`, whose client then WRITES `MAP.md` files under the returned root — `rgr/src/commands/map.rs:96-131` creates directories there), and in the storage crate the document inventory behind orient and `modules list` (`storage/src/agent_orient_reads.rs:65`) and the enrichment root (`storage/src/enrichment_impl.rs:822`). After a state root moves to a directory at a different depth, these surfaces fail with a wrong cause (`failed to spawn git`), report an absence (`No README or architecture doc found`; zero matched coverage files; no `Docs:` line), or would write files outside the repository. Each request is routed through the registry entry that holds the absolute `canonical_path` (`state.rs:1207 resolve_alias_or_path`), and the entry is dropped before any reader runs (`handlers/support.rs:22-50`, `dispatch.rs:243`, `:279`). The seam map and its search basis are in the operator's working notes; a text search, confirmed in the slice by removing the db-relative helpers so the compiler lists every caller.

**Options (reward / risk).**
- A — one source, passed explicitly: the daemon keeps the registry `canonical_path` when it resolves a request (and, for passes keyed by store path and repo uid, finds the entry by those two keys) and passes the root as an argument to every working-tree reader; the storage reads take the root as a parameter; the db-relative helpers (`resolve_root_path`, `resolve_repo_root_abs`, `resolve_root_against_db_parent`, the two inline joins) are deleted, so the compiler lists every former caller; a reader that needs the root and has none returns a named error. Reward: one rule with no hidden state; the deletion turns "did we find every site" into a compile error; tests can pass any root. Risk: signature changes through the enrichment pipeline and the document-inventory reads (the storage port and its test fakes).
- B — store the root on the in-memory repo state at load and read it from there. Reward: fewer signatures change. Risk: per-load state that a legacy load path (`load_repo {db_path, repo_uid}`) can leave empty, so a missed path degrades silently; a second place that holds the fact.
- C — keep the joins and fall back to the registry when the joined path does not exist. Reward: smallest diff. Risk: two sources that can disagree with neither failing, which is the defect this slice removes.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A**; the human may override. Scope, every one bound to RG-REQ-011-L13: the eleven sites above; refresh's hand-off to the auto-enrich and seed passes uses the same registry root; `docs list`/`docs extract` JSON `repo_path` carries that absolute root. When the root directory does not exist or is not a directory, each surface names it with the one prefix `repo root not found: <absolute path>`: an error on docs list/extract, churn, hotspots, risk, coverage, map (before any file is written) and refresh; `IndexDrift::Unknown` with that reason (no git spawn) on orient, check and explain; the orientation-docs `unavailable` state on orient and `modules list` (`Orientation docs unavailable: repo root not found: …`, the RG-REQ-008-L07 read-failure form), never the no-docs recommendation; a failed enrichment attempt with that reason. Out of scope, recorded as residuals: the orient headline `Docs:` line is omitted (not asserted) when the inventory is unavailable — giving it an explicit unavailable state is a DTO change for its own slice; the client-side `rgr/src/cli/context.rs resolve_repo_root` has no caller and stays (dead code, a separate cleanup); `compute_storage_root_path` and the stored bytes are unchanged (D-SRR-ROOTPATH-1).
