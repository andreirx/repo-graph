# D-DGC1B-MAP-GRAMMAR-1 — the Groovy alias map is readable only under one closed grammar: literal `libs = […]` / `libs += […]` statements at the applied script's top level or inside an unconditional `ext { }`, evaluated in statement order; any other assignment form makes the whole map unreadable and every dependent reference is counted

Raised: 2026-10-04 by the manager at the checkpoint after DEPS-GRADLE-CATALOG-1B-PREP reached its cap (5 document cycles in the INPUT-4 admission; reviewer codex gpt-6-sol): four consecutive findings in one class — an interpolated artifact (D-DGC1B-ARTIFACT-INTERPOLATION-1), statement applicability (D-DGC1B-ALIAS-APPLICABILITY-1), a map assignment under a condition inside an unconditionally applied script (review-3, F-DGC1B-MAP-SCOPE), and the order of `libs =` replacement and `libs +=` addition (review-4, F-DGC1B-MAP-ORDER) — each true, each with zero corpus rows.

**The problem in plain words.** The slice resolves kafka's 365 `libs.<alias>` references through a Groovy script (`gradle/dependencies.gradle`) that BUILDS the alias map by assignment. A static reader can only assert what the script states unconditionally; every review cycle found another way a cleverer script could make the reader assert a group the build would not produce. MEASURED: kafka's `libs` statements are exactly `ext { libs = [:] }` (:22, inside the unconditional `ext { }` block) and one top-level `libs += [ … ]` (:145); the script's `if` statements (:27-43) touch `versions.scala` only; grpc-java uses the TOML catalog; no other repository in the corpus has a Groovy alias map. The product result of the slice (kafka `clients` `used 0 → 26`, grpc-java `core` `0 → 4`) was already produced by admission 2's candidate.

**Options presented to the human (reward / risk, by usefulness to an agent net of misdirection).**
- A — closed grammar, one more cycle: a map named `libs` (or the name the `libraries = …` rename resolves through) is READABLE only when EVERY statement in the applied script that assigns to it is a literal map `libs = [ … ]` or `libs += [ … ]` at the script's top level or directly inside an unconditional top-level `ext { }` block; the statements are evaluated in order (`=` replaces the map, `+=` adds entries; an entry's group is its literal first segment, D-DGC1B-ARTIFACT-INTERPOLATION-1); any other assignment form anywhere in the script — under `if`/`else`, in a loop, in any other closure or method call, a non-literal right-hand side, `libs.put`, `libs[...] =` — makes the WHOLE map unreadable, and every alias reference that depends on it is counted with `first` stating `{path}:{line} {accessor}: alias map in {script}:{stmt line} is not a top-level literal assignment`. Reward: kafka binds exactly as today's candidate binds it; the class is closed by one rule, not by the next example; a repository with a cleverer script gets investigation notes instead of bindings — unhelped, never misled. Risk: one more document cycle and a third implementation admission.
- B — drop the Groovy map source from 1B (TOML only). Risk: kafka's 365 references stay unresolved; `clients` stays `used 0`; the slice's main measured outcome is lost.
- C — defer the slice. Risk: both repositories keep every catalog dependency undeclared.

Resolved: 2026-10-04 by the HUMAN: **"Closed grammar, one more cycle (Recommended)"** — option A.
