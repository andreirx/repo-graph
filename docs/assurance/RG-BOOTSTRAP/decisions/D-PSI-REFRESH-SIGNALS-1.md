# D-PSI-REFRESH-SIGNALS-1 — On a delta refresh, does the resolver see the import bindings of files that were copied forward?

Raised: 2026-09-23 by the document item PYTHON-SUBMODULE-IMPORT-1-PREP-2 (requirements author claude-opus-5-5, D-PSI-03; reviewer codex gpt-6-sol, F-PSI-REFRESH) and VERIFIED by the manager on the source: `indexer/src/orchestrator.rs` fills `all_signals` during extraction (:521, :702) and builds the resolver's `import_bindings_by_file` from it (:1007 `build_import_bindings_map(&all_signals)`); on a refresh the copied-forward files' `file_signals` rows are copied into the child snapshot (storage, "Copy file_signals") but never loaded into that map, although the port `query_file_signals_batch` (indexer/src/storage_port.rs:469) exists. PYTHON-SUBMODULE-IMPORT-1's rule consults ANOTHER file's bindings (the package init's), so a `from X import Y` in a changed file whose unchanged `X/__init__.py` imports `Y` from elsewhere would bind to the submodule (inferred, alternate = the init) after a refresh where a full index keeps the init (static). The same absence already affects the namespace-import stage and unresolved classification for every language on refreshed stores — a pre-existing refresh ≠ full-index discrepancy against RG-REQ-001-L09 ("the same source yields the same graph").
Resolved: 2026-09-24 by the OPERATOR — option A. The human may override.

## Options
- **A (ratified by the operator)** — the orchestrator loads the copied-forward files' signals (`query_file_signals_batch` over the copy-forward set) into `all_signals` before `build_import_bindings_map`, so the resolver's inputs on a refresh equal a full index's. Reward: refresh equals full index for this stage AND the pre-existing gap in call resolution and classification closes on refreshed stores (RG-REQ-001-L09 restored); the fix is one data-path load through an existing port, no new mechanism. Risk: CALLS resolution and unresolved classification on refreshed stores of every language may move (toward the full-index answer) — the slice binds a refresh-parity oracle (full index vs no-change refresh: identical IMPORTS and CALLS edge sets on the fixture and on django) so the movement is proven to be toward parity, never away.
- **B** — ship the stage as specified and state the residual (only the init-imports-Y-from-elsewhere shape; the error is toward an inferred edge naming the right alternate; `rmap repo rebuild <path>` restores). Reward: the smallest slice. Risk: a known refresh discrepancy shipped on purpose against L09 and agent_docs/architecture.md ("a feature working only on full index is incomplete"); the residual grows with every rule that consults another file's facts.
- **C** — a prerequisite slice for the signals load. Reward: PSI1 stays narrow. Risk: one more admission and review for a one-load change that PSI1 must test anyway; sequencing cost with no product reward.
