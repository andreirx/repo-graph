# D-DD1-003 — Does documentation discovery match the file extension case-insensitively (`README.TXT`, `README.MD`)?

Raised: 2026-09-21 by the RG-BOOTSTRAP-INPUT-6 standalone review (codex gpt-5.6-terra, pass 1 finding 3): the ratified RG-REQ-008-L01 statement did not state case behaviour, today's code compares extensions byte-for-byte (`ends_with(".md")`), and CC-8's measured expectation had silently assumed case-insensitivity for `extras/README.TXT`. The manager removed that expectation and put the question to the human.
Resolved: 2026-09-22 by the HUMAN — "extension matching case insensitive".

## The problem

A file's STEM is its name minus a recognised documentation extension, or the whole name when no documentation extension is recognised ("with or without a documentation extension" — `README.html` is refused because `.html` is not a documentation extension, so its stem is `readme.html`, not `readme`). The stem set is written in lowercase and must match `README`, so the stem comparison is necessarily case-insensitive. The extension list `{.md, .markdown, .txt, .rst, .adoc}` is also written in lowercase, but today's code recognises it byte-for-byte, so `.TXT` and `.MD` were not documentation extensions: django's `extras/README.TXT` had the stem `readme.txt` and langchain4j's `langchain4j-milvus/README.MD` the stem `readme.md` — neither in the set — while `readme.txt` (lowercase extension) was admitted. The extension's case therefore decides the stem branch too; it is one matching rule, not two.

Measured on the 17 checkouts: those two files are the ONLY uppercase-extension documentation files anywhere; both qualify through the stem branch once the extension is recognised case-insensitively. No file qualifies only through the extension-in-doc-tree branch (no uppercase-extension file exists inside any docs tree), so the doc-tree branch has no corpus-count consequence today — the clause still governs it (a `docs/NOTES.MD` would be admitted).

## Resolution

RG-REQ-008-L01's statement: "both the stem and the extension are compared case-insensitively". Measured consequence (CC-8 revised): django 616 → 622 documents (`extras/README.TXT`, stem branch), langchain4j +1 (`langchain4j-milvus/README.MD`, stem branch); every other corpus unchanged. Standalone review of INPUT-7, pass 1 (codex gpt-5.6-terra): REFINE — the record had not stated how the stem is derived from the extension; corrected above. Carried by RG-BOOTSTRAP-INPUT-7 (standalone review + operator approval 7, same commit) and by DOCS-DISCOVERY-1-INPUT-1.
