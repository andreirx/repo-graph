# D-TSA-BOUNDED-SCOPE-1 — a `paths` alias binds STATIC only for a file covered by exactly one inspected tsconfig project; multi-project files are out of this slice's scope and left as at HEAD

Raised: 2026-10-03 by the manager at the checkpoint after the INPUT-5 document review (cycle 4 of this admission, the sixth document cycle; reviewer codex gpt-6-sol; decisions D-TSA5-COUNTS-ON-THE-PORT and D-TSA5-PROJECT-COVERAGE).

**The problem in plain words.** The slice binds TypeScript `paths` alias imports to their files: 512 corpus rows (amodx 416, hexmanos 95, storybook 1), every one a file covered by exactly ONE tsconfig project whose mapping selects exactly one indexed file. Cycles 2–5 of the document review were one question asked more precisely each time: when several tsconfig projects cover one source file, what may a STATIC edge claim? TypeScript resolves per project, so two projects can bind one specifier to two files; D-TSA-RECORD-CONFLICT-1 makes STATIC assert the compiler's binding. Each successive rule (nearest config wins → union of hits → every covering project agrees) either could emit a static edge one compiling project does not make, or needed two counts the agent port cannot carry (`AgentUnresolvedImportEntry`, `agent/src/storage_port.rs:1511`; storage `queries.rs:292-333`; daemon `import_partition_view.rs:449-463` — three paths outside the allocation and a data shape crossing the agent port), or left "every project" undefined (a sibling tsconfig anywhere in the repository may list the file; the reader inspects the nearest tsconfig and its one-level `references`). MEASURED (author, before stores, `immutable=1`): zero corpus rows are in the multi-project case.

**Options presented to the human (reward / risk, by usefulness to an agent net of misdirection).**
- A — bounded static, scope cut: the alias stage binds only when exactly ONE inspected project (the nearest `tsconfig.json` after its `extends` chain, and its one-level `references`, each by membership per D-TSA-CONFIG-APPLICABILITY-1) covers the file, has `paths`, and TypeScript's selection under that mapping yields one indexed file; several files under that one project → the allocated ambiguous row with every candidate; the contract states the reader's scope as a limit. A file covered by zero or two-or-more inspected projects: the stage DECLINES BEFORE MATCHING — nothing known is dropped — and the row stays exactly as at HEAD (phrase `specifier matches a tsconfig paths alias`; the workspace stage runs as at HEAD). Reward: all 512 corpus imports bind as the compiler binds them; no port field, no repo-wide scan, within the sixteen paths. Risk: an agent on a multi-project file (none today) is unhelped, not misled; a project elsewhere listing the file is outside the stated scope.
- B — full multi-project semantics: counts on the agent port (+3 paths), repo-wide membership scan. Reward: counts and a repo-wide project basis. Risk: a boundary DTO change and at least two more document cycles for zero observed rows.
- C — INFERRED instead of static. Risk: reverses the human's static ruling; 512 compiler-certain bindings hidden from the default views.
- D — defer the slice. Risk: 512 measured imports stay without a confirmed target.

Resolved: 2026-10-03 by the HUMAN: **"Bounded static, scope cut (Recommended)"** — option A.

## What this record rules
- Scope: the alias stage's reader scope is the nearest `tsconfig.json` (after its relative `extends` chain) and its one-level `references`; projects outside it are not consulted, and the contract states this limit beside the existing ones (package `extends` unread).
- Binding: STATIC (D-TSA-RECORD-CONFLICT-1, basis `tsconfig_paths`) only when exactly one inspected project covers the file and its mapping selects one indexed file; several files under that mapping → `TsconfigPathsAmbiguous` with every candidate (basis `ambiguous_tsconfig_paths`; phrase restating the one-project predicate: `the tsconfig paths that apply to this file reach {m} indexed files`); no hit → no binding (D-TSA-RECORD-CONFLICT-1's clarification: the workspace stage runs).
- Out of scope: a file covered by zero or several inspected projects takes no aliases from this stage; the row stays as at HEAD. No counts, no carrier fields, no port change. A follow-up TS-ALIAS-MULTI-PROJECT-1 is filed for the day the corpus shows such a row.
- Superseded: D-TSA-MIXED-PROJECT-1's agreement rule, counts and counted phrase; D-TSA-CONFLICT-EVIDENCE-1's union over projects (the union within ONE project's mapping stands); D-TSA-CONFIG-APPLICABILITY-1's "the distinct effective mappings of ALL covering projects feed the stage" (membership and the no-covering-project decline stand).
