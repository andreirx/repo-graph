# D-JSAH-INCOMPLETE-CURSOR-1 — when an ambiguity payload cannot form a candidate's command, the listing keeps the row, prints no cursor line for it, and says what is unavailable

Raised: 2026-10-05 by the implementation reviewer of JAVA-SYMBOL-AMBIGUITY-HINT-1 (admission 2, cycle 1; the reviewer's label JSAH-INCOMPLETE-CURSOR-1), with two findings in the same pass (JSAH-ZERO-LINE, JSAH-MISSING-WITNESS).

**The problem in plain words.** The listing prints one runnable command per candidate (`→ rmap callers '<key>'`). Two inputs defeat that: for `path`, the daemon's `data.query` names which argument was ambiguous — when it is absent or matches neither argument, the candidate's `(prefix, suffix)` pair is empty and the admission-2 renderer printed `→  '<key>'`, which is not a command, under a hint that says to run it; and a candidate without a `stable_key` has nothing to quote. The current daemon always sends `query` and `stable_key` (`dispatch.rs:2738–2816`), so this is a source-proved defensive path, not a reproduced failure — but RG-REQ-012-L03 says every printed cursor runs as printed, and the accepted byte form prescribed one cursor per candidate without exception. Two more defects were found alongside: `candidate_rows.rs` reads `line_start` raw and the renderer prints `file:0` for the store's 0 sentinel (RG-REQ-012-L07 — the established render chokepoint is `presentation::anchor`, which omits non-positive lines, and storage reads normalise 0 → None); and admission 2's report did not record the daemon-crate witness `daemon-runtime/tests/consolidation_witness.rs` that CLAUDE.md requires for a touched daemon crate.

**Options for the incomplete payload (reward / risk).**
- A — keep the candidate rows and every known key; for a candidate whose command cannot be formed print NO `→` line; replace the run hint by `hint: this listing is incomplete — <reason>` (reasons: `the daemon did not say which path argument was ambiguous`; `a candidate has no stable key`); with an absent `query` the header reads `Candidates (N) — pick one by its stable key:` (no `each matches '?'`). Reward: honest evidence, no false next command, nothing lost. Risk: amends the one-cursor-per-candidate wording for incomplete payloads; two renderer tests.
- B — print a labelled `rmap explain '<key>'` fallback where a key exists. Reward: an actionable step. Risk: it is not a `path` continuation; a missing key still needs an unavailable state.
- C — fail the whole listing as a runtime error. Risk: loses the other candidates.
- D — keep the candidate as is. Risk: a non-command presented as runnable; L03 unmet on that path.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A**, implied by RG-REQ-012-L03 and RG-REQ-002-L04; the human may override. The same amendment (INPUT-3) binds: `symbol_row_by_stable_key` normalises `line_start` 0 → `None` (the storage DTO chokepoint, as the other reads do) and the renderer anchors with `presentation::anchor` (so neither JSON nor the human row can carry `:0`); JSAH-C01 runs `cargo test -p repo-graph-daemon-runtime --test consolidation_witness` and asserts its pass.
