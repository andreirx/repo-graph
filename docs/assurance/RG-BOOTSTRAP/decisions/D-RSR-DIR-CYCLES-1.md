# D-RSR-DIR-CYCLES-1 — `cycles` runs over directory groups, so binding a crate's own `use` paths adds directory edges inside crates; the movement is accepted and asserted, not hidden

Raised: 2026-10-04 by the RUST-SELF-RESOLUTION-1 document author (cycle 1, claude-opus-5-5): `DECISION_REQUIRED D-RSR-DIR-CYCLES-1`.

**The problem in plain words.** `cycles`, `orient`'s cycle line and `explain`'s Import-cycles block do not run over Cargo crates. They run their SCC over DIRECTORY groups — the population `stats` calls "directory groups" (`storage/src/directory_module_edges.rs:1-24`, D-TESB-03). RUST-SELF-RESOLUTION-1 binds `use` paths between files of one crate; when the two files sit in different directories (`handlers/quality/tests.rs` → `handlers/support.rs`; `presentation/cycles/walk.rs` ↔ `presentation/cycles/mod.rs`), that is a new DIRECTORY edge. Measured by the author on the HEAD-built before-roots (the default view's SCCs recomputed from the before stores, reproducing `before/rg-cycles.txt` exactly, then with the predicted edges added): repo-graph `1 module-level cycle found` → 8 (new cycles inside `daemon-runtime`, `agent`, `rgr`, `storage`, `module-queries`, `repo-index`, `state-extractor`); zap-engine 1 → 2; codegraph 3 → 3 with the same member sets. The packet's "cycles unchanged" oracle and stop condition (c) were false — the manager assumed the cycles population was Cargo modules.

**Options (reward / risk, by usefulness to an agent net of misdirection).**
- A — accept the movement; RSR-C05 asserts the derived cycle sets (before edges + the replay's predicted edges, mapped to their directory groups, through the same SCC rule) instead of a byte comparison; the ship record states the movement. Reward: the store and the directory graph stay true; every new cycle is a real import cycle between directories. Risk: a Rust parent ↔ child module reference (`mod.rs` declares and uses a child; the child uses `super::`) renders as a "module-level cycle" — the normal shape of a Rust module tree read as a finding (RG-REQ-002-L08: the label describes `stats`' directory groups, not Cargo modules — a pre-existing wording question, CYCLES-STATS-POPULATION-1).
- B — exclude intra-crate directory edges from the directory graph. Reward: today's `cycles` output. Risk: the directory graph silently omits true edges; the frozen cycles derivation changes — a slice of its own.
- C — defer the slice. Risk: RC-13 stays open; the agents keep working blind on repo-graph.

Resolved: 2026-10-04 by the OPERATOR (in-place manager) as **A** (the author's recommendation; RG-REQ-002-L10 lets a headline move with its cause stated); the human may override. Follow-up: CYCLES-RUST-POPULATION-1 — for a Rust crate, state on the cycles row that the members are directories of one crate, or run the SCC over Cargo crates (joins CYCLES-STATS-POPULATION-1).

## What this record rules
- RSR-C05 replaces `cmp` on `cycles` with an oracle: the AFTER `cycles` member sets (default view) equal the SCCs of the BEFORE directory edges plus the predicted new file edges mapped to their owning directory groups, computed by the replay from the before store; the count and the new cycles are printed and quoted in the ship record.
- Stop condition (c) and P-RSR-05 name the Cargo-module graph (`modules list`/`modules deps` cross-module counts, trust's module connectivity) as what stays unchanged; `cycles` is the stated movement.
