# D-DGC1B-ALIAS-APPLICABILITY-1 — a catalog rename (`libraries = libs`) or an applied alias map counts for project P only where its statement's scope reaches P under 1A's attribution rule; a reference that depends on a statement not shown to apply is counted, never bound

Raised: 2026-10-04 by the implementation review of DEPS-GRADLE-CATALOG-1B admission 2 (cycle 0; reviewer codex gpt-6-sol; F-DGC1B-ALIAS-APPLICABILITY and its decision D-DGC1B-ALIAS-APPLICABILITY).

**The problem in plain words.** VERIFIED on the candidate: `config.rs` recorded `libraries = libs` as a script-wide boolean (`libraries_is_libs`) without its enclosing scope, and `gradle_catalog.rs` bound every `libraries.*` reference of the build when ANY script of the build carried the rename (`scripts.iter().any(…)`); the applied-map collector likewise did not reject a conditional source. Counterexample (the reviewer's, by source inspection): `a/build.gradle` says `libraries = libs`; `b/build.gradle` defines its own `libraries.foo` and declares `implementation libraries.foo`; if the TOML catalog also has `foo`, the reader binds b's declaration to the TOML group — a declared row b's own Gradle source does not support. RG-REQ-006-L13 already rules the shape of the answer: "other projects' blocks are never attributed to P". MEASURED on the corpus: grpc-java's `libraries = libs` (`build.gradle:159`) sits in the root script's `subprojects { }` block — applies to every non-root project, `core` included; kafka's `apply from: "$rootDir/gradle/dependencies.gradle"` (`build.gradle:23`) sits unconditionally in the root script's `buildscript { }` block — the whole build. No corpus row moves under either option.

**Options (reward / risk, by usefulness to an agent net of misdirection).**
- A — scope the statements as 1A scopes `dependencies` blocks: a rename or an `apply from:` applies to P when it sits at the root script's top level or in its `buildscript { }` (the whole build), in a root `allprojects { }` (every project) or `subprojects { }` (every non-root project), at the top level of P's own script, or in a root `project(':P') { }` block; a statement anywhere else (a sibling project's script, a conditional, a closure or task body, `afterEvaluate`) does not apply to P. A reference whose binding would depend on a non-applicable statement is counted on the build's record with `first` stating `{path}:{line} {accessor}: rename/map at {stmt path}:{stmt line} not shown to apply to this project`; the TOML catalog of the settings directory applies to the whole build as before. Reward: a declared row rests on a statement Gradle would evaluate for that project; grpc-java and kafka unchanged; the uncertain case is marked with the site to open. Risk: one more scope the reader tracks (the 1A scope model reused, no new vocabulary beyond the `first` reason); fixtures only — zero corpus rows.
- B — support `libraries.*` only when the rename sits in the referencing project's own script. Risk: grpc-java's `subprojects` rename stops applying and `core` loses its 11 groups — a ratified L13 outcome reversed.
- C — defer. Risk: L13 undelivered over a zero-row case.

Resolved: 2026-10-04 by the OPERATOR (in-place manager) as **A** — the application of L13's attribution rule to the two statements this slice introduces, not a new rule; overridable by the human. Tests bound: the sibling-script rename counterexample (b's reference counted, not bound; a's own references bound), a conditional `apply from:` (counted), the root `subprojects` rename (every subproject bound — grpc-java's shape), the root `buildscript` apply (whole build — kafka's shape).
