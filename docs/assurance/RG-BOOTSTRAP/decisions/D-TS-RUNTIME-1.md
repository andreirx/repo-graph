# D-TS-RUNTIME-1 — Three runtime questions of TOOLCHAIN-STALENESS-1's automatic re-index

Raised: 2026-09-26 by the document review of TOOLCHAIN-STALENESS-1-PREP-2 (reviewer codex gpt-6-sol; decisions D-TS-STDIO, D-TS-INCLUDE-ROOTS, D-TS-FIELD-PROOF).
Resolved: 2026-09-26 by the OPERATOR under the human's standing rule of the same day (D-STALE-SIGNAL-1: questions about staleness mechanics are decided, not escalated). The human may override.

## 1. D-TS-STDIO = A — a stdio daemon reports `disabled`, it does not re-index
Verified: `run_daemon_stdio` (`daemon-runtime/src/lib.rs:389`) serves one client and returns at stdin EOF, so a background job started by it is killed when the request ends; the next invocation would start it again and never finish (each kill leaves a `building` snapshot that crash-orphan reconciliation marks interrupted). The stdio transport is the CLI's sandbox fallback, not the resident daemon users run. Resolution: under the stdio transport the re-index state is `disabled` with the reason `stdio transport — a background re-index cannot outlive the request`, and the line carries the rebuild suffix; the resident (socket) daemon behaves as L06 states. Rejected: B (synchronous re-index before the response — a request that takes the full index duration, and the old snapshot is not served meanwhile); C (a worker process that outlives the client — a new process-lifecycle mechanism in exactly the environment that forbids sockets).

## 2. D-TS-INCLUDE-ROOTS = A, with the pre-existing gap filed — the automatic re-index uses the inputs a plain refresh uses
Verified: user-supplied C/C++ include roots are never persisted — `handle_index` reads `include_roots` only from request parameters (`dispatch.rs:3097-3110`), `rmap refresh` takes the same `--include-root` flag (`rgr/src/commands/index.rs:1358-1406`) and the orchestrator reads them from the options of each run (`orchestrator.rs:290`, `:1997`); no registry or snapshot field holds them. So a plain `rmap refresh` without the flags ALREADY resolves with the derived roots only (CPP-INCLUDE-ROOTS-1) — the loss the reviewer names is a property of every flagless write today, not something this slice introduces. Resolution: the automatic re-index is a flagless full index (derived roots only), stated in the slice's §3 as a known limitation with the same behaviour as `rmap refresh`; persisting the effective include roots for EVERY write path (refresh, index, automatic re-index) is follow-up INCLUDE-ROOTS-PERSIST-1, one data-shape change for all three. Rejected: B inside this slice (persists roots for one of three write paths — the refresh path would keep losing them); C (withholding re-index needs a durable marker of which repositories use custom roots — the same persistence B needs).

## 3. D-TS-FIELD-PROOF = A — mechanism proof now, the real-upgrade field criterion at the first version bump
Verified: the retained v0.19.0 leveldb store's stamp equals the current running toolchain (no component has changed since v0.19.0), so no real store is stale today. Resolution: this slice's field check mutates the stamp of a COPIED store (mechanism proof: comparison, scheduling, serving the old snapshot, completion); L06's field criterion ("a store indexed by v0.19.0, first queried by the next binary, re-indexes in the background and then reports current") stays UNVERIFIED in this slice's report and is executed by the operator at the closeout of the first implementation that bumps a version (CPP-ATTRIBUTE-MACRO-1A in the queue), on a retained v0.19.0 copy with the candidate binary. Rejected: B (a gratuitous version bump — every existing store re-indexes for nothing); C (hold this slice until another ships — it is the gate those slices wait on).
