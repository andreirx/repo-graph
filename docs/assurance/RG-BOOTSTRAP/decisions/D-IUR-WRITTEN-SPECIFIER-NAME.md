# D-IUR-WRITTEN-SPECIFIER-NAME — the unresolved row's recorded specifier is named `recorded_specifier` (the extractor's `rawPath`), never "written"

Raised: 2026-10-03 by the document review of IMPORTS-UNRESOLVED-REMAINDER-1 (INPUT-2, cycle 7; reviewer codex gpt-6-sol; `.agent-manager/slices/IMPORTS-UNRESOLVED-REMAINDER-1-PREP/review-6.json`, local; finding F-IUR-13).

**The problem in plain words.** The manager's F-IUR-12 revision added a DTO/JSON field `written_specifier` carrying the extractor's recorded `rawPath`, meant to show the import "as written". The C and C++ extractors record a quoted include with a `./` prefix (`c-extractor/src/extractor.rs:351`, `cpp-extractor/src/extractor.rs:625`): leveldb `table/table_test.cc:10` says `#include "gtest/gtest.h"` and the store holds `rawPath: "./gtest/gtest.h"`. So the value is the specifier as RECORDED, not as written — the name was a conclusion (D-AGENT-USEFULNESS-FRAME-1's class), and the packet's own freeze forbade the reviewer from renaming a boundary field.

**Options (reviewer's table, reward / risk).** A — rename to `recorded_specifier`: the name is true for every extractor, the human row and stored facts are unchanged; lifts the freeze for one boundary name, one coordinated edit. B — keep the name and make the value the source spelling: extractor-specific branching and a preservation proof per language. C — keep name and value: a false boundary name reaches JSON consumers. D — defer the slice.

Resolved: 2026-10-03 by the OPERATOR (in-place manager) as **A**, overridable by the human. The field is `recorded_specifier`: the specifier string as the extractor recorded it in `metadata_json.rawPath` (a C/C++ quoted include carries a `./` prefix; a TS/JS import is recorded as spelled), `null` when no `rawPath` string is stored. The human row prints it verbatim and claims nothing about the source spelling. The freeze is lifted for this one name only; no other phrase, field or test name changes beyond the rename and F-IUR-14's predicate restatement.
