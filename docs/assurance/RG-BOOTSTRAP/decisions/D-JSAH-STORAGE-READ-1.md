# D-JSAH-STORAGE-READ-1 — one narrow public storage read by stable key, in a new storage file, supplies each ambiguous candidate's stored identity, anchor and signature

Raised: 2026-10-05 by the requirements author and the requirements reviewer of JAVA-SYMBOL-AMBIGUITY-HINT-1-PREP (cycle 1), independently and in agreement.

**The problem in plain words.** The INPUT-1 allocation told the daemon to look each ambiguous stable key up with `storage.query_symbol_by_field` and to print the candidate's signature. That function is `pub(crate)` inside the storage crate (`rust/crates/storage/src/queries.rs:3687`), so `daemon-runtime` cannot call it; the `ResolvedSymbol` it returns has no `signature` field (`queries.rs:72-81`); and the same allocation froze `rust/crates/storage/`. The seam as written could not compile, and RG-REQ-005-L05 revision 2 requires the signature — the only text that tells two overloads apart. The public alternatives each cover part of the need: `get_symbol_context` has no signature, `find_fact_symbols` is a name search (its limits can omit a resolver candidate), `map_symbols_in_path` has no stable key.

**Options (reward / risk).**
- A — ONE narrow public read, in a NEW storage file `rust/crates/storage/src/candidate_rows.rs` (declared in `storage/src/lib.rs`): `impl StorageConnection { pub fn symbol_row_by_stable_key(&self, snapshot_uid: &str, stable_key: &str) -> Result<Option<SymbolRow>, StorageError> }` — one SQL query by `stable_key` over `nodes` joined to `files`, returning the raw DTO `SymbolRow { stable_key, name, qualified_name: Option, kind, subtype: Option, file: Option, line: Option<i64>, signature: Option }`. `queries.rs` (the shared resolver `resolve_symbol` and `ResolvedSymbol`) stays byte-identical, proved by JSAH-C02. Reward: one explicit reader per fact; the resolver and its DTO untouched; no coupling to `find`'s search. Risk: the storage crate is no longer wholly frozen — one file is added; the allocation is re-baselined.
- B — reuse `find_fact_symbols(snapshot, query, usize::MAX)` and filter by key. Reward: no storage change. Risk: the listing silently depends on `find`'s LIKE semantics; a candidate the search misses is listed with nulls; a full scan on the error path.
- C — make `query_symbol_by_field` public and add `signature` to `ResolvedSymbol`. Risk: changes the resolver's shared DTO and its nine literal constructions across storage and daemon-runtime.
- D — drop the signature or defer. Risk: contradicts RG-REQ-005-L05 revision 2; the agent still cannot choose an overload.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A**; the human may override — this amends a path the operator had frozen (`rust/crates/storage/`), so it is also reported to the human as a frozen-path amendment. The slice's `candidateExclusions` no longer exclude the storage crate as a whole; JSAH-C02 asserts `rust/crates/storage/src/queries.rs` and `agent_impl.rs` byte-identical to HEAD.
