# D-SRR-DOCTEST-IDENTITY-1 — SRR-C01's retention oracle compares doctests without their source line number, and fails on any collision

Raised: 2026-10-05 by the implementation reviewer of STATE-ROOT-RELATIVE-REPO-ROOT-1 (admission 1, cycle 1; codex gpt-6.1-sol; DECISION_REQUIRED SRR-C01-DOCTEST-IDENTITY), agreeing with the builder (claude-opus-5-5), who reported the same cause and declined to move code to satisfy the check.

**The problem in plain words.** SRR-C01's `c01-retained` marker requires that, per crate, the HEAD test names missing after the change are exactly the eight retired tests. `cargo test -- --list` names a doctest by its file, item AND source line: `crates/daemon-runtime/src/lib.rs - require_global_mode_for_authority_write (line 223)`. The slice must add `mod repo_root;` to `daemon-runtime/src/lib.rs` (SLICE_DOC §2.1, the guardrail placement), which moves that doctest to line 224. The test still exists and still reports `1 ignored`, as at HEAD, but the oracle sees one HEAD name missing and fails. The operator verified it on the candidate: the only unauthorized missing name is that doctest, present as `(line 224)`. The defect is in the oracle the operator wrote, not in the candidate.

**Options (reward / risk).**
- A — compare names after removing only a trailing ` (line N)` suffix, and fail if that normalization merges two distinct names in either list. Reward: a test is identified by what it is, not where a required edit pushed it; the exact retirement set and every assertion are unchanged. Risk: two doctests of the same item in one file would merge — the collision check turns that into a failure, never a silent merge.
- B — defer acceptance and keep the oracle. Reward: the baseline stays as approved. Risk: the slice cannot pass a check that fails on a correct candidate; the only other route is moving code to fit the check, which both the builder and the reviewer rejected.

**Resolved: 2026-10-05 by the OPERATOR (in-place manager) as A** — the reviewer's recommendation; the defect is the operator's own oracle; the human may override. Applied in STATE-ROOT-RELATIVE-REPO-ROOT-1-INPUT-2 (SRR-C01): both lists are normalized with `sed -E 's/ \(line [0-9]+\)$//'`; the unique-name count before and after normalization must be equal in both lists (no collision); the missing set is then compared with the retired list exactly as before.
