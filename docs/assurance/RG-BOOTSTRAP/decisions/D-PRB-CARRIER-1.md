# D-PRB-CARRIER-1 — What proves that `self`/`cls` in a Python class-body call is the method's receiver, before a hierarchy binding is certain

Raised: 2026-09-24 by the fourth document review of PYTHON-RECEIVER-BINDING-1 (reviewer codex gpt-6-sol, D-PRB-CARRIER-SEMANTICS, finding F-PRB-CARRIER-LEXICAL-BINDING). The self-call carrier (`python-extractor/src/extractor.rs:1109-1120`) is stamped from a two-part `self.m`/`cls.m` key and `current_class` alone: it proves CLASS CONTEXT, not what the identifier denotes. The reviewer executed the counterexample: `import math as self` at module level and a parameterless class-body function calling `self.sqrt(4)` returns 2.0 from the alias although the class defines `sqrt`. Revision 5's rule (hierarchy stage first whenever the carrier is present) would emit a certain edge to the class method there.
Resolved: 2026-09-24 by the OPERATOR — option C. The human may override.

## Measured (django checkout, Python `ast`, 2026-09-24)
50,080 `self.m()`/`cls.m()` calls inside class-body functions; 50,075 have the receiver identifier equal to the enclosing function's FIRST parameter; 0 are in `@staticmethod`s; 5 are not (e.g. `tests/generic_views/test_base.py:190` uses `cls` inside a method whose first parameter is `self`; `django/db/models/manager.py:87` and `django/views/generic/base.py:99/:105` use `self` inside functions whose first parameter is `cls`; `tests/model_inheritance/tests.py:294` first parameter `self_`). 0 imports aliased `as self`/`as cls`. The proof covers 99.99% of the corpus; the remainder is exactly the class that must not be certain.

## Options
- **A** — keep revision 5 (class context alone grants the hierarchy stage). Reward: no extractor change. Risk: a certain edge on a name coincidence — the class RG-REQ-005-L02 forbids; the reviewer has a running counterexample.
- **B** — on a carrier/namespace-alias collision, keep both candidates and stay unresolved. Reward: no false certain edge. Risk: a real parameter that shadows an alias loses its binding; the rule is keyed on the alias's presence, not on the receiver's binding — proof by absence of a competitor.
- **C (ratified by the operator)** — the extractor records the receiver's lexical binding: the carrier gains `receiverBinding: "parameter"` when the receiver identifier equals the enclosing function's first parameter and the function is directly in the class body and not a `@staticmethod`; otherwise `receiverBinding: "unproven"`. The resolver runs the hierarchy stage only for `"parameter"` (hit → static; miss → unresolved `self_call_hierarchy_miss` with the pool); `"unproven"` → unresolved `self_call_receiver_unproven` with every candidate (the hierarchy candidates and any same-named namespace alias target); a carrier WITHOUT the field is one an older extractor wrote (copied forward) and keeps today's class-context binding — a stale extraction fact RG-REQ-001-L06 reports until rebuild; a wrong-typed field is unreadable → unresolved with the pool. Reward: every certain self-call edge rests on a lexical fact the extractor read; the 5 django outliers become honest unresolved rows; the extractor version bump marks the stale carriers. Risk: `rust/crates/python-extractor/src/extractor.rs` (the carrier and a tracked enclosing-function first parameter beside `current_class`) and its tests join the allocation with the extractor version; five django rows move from certain to unresolved (true).
- **D** — defer. Reward: none over C. Risk: the audit's first-ranked class waits.

## Resolution
C. Tests: extractor — parameter receiver (`self`, `cls`), a `@staticmethod`, a nested function, a first parameter named otherwise, a call outside a class (no carrier); resolver — `"parameter"` hit and miss, `"unproven"` with a colliding alias (both candidates recorded), field absent (today's binding), field wrong-typed (unresolved). Field literals: django 50,075 proven / 5 unproven; the ship block names the five rows. The `import helper as self` shadowing tests of PREP-4 are replaced by these.

## Correction 2026-09-24 (operator; PREP-5 review — decision D-PRB-LEGACY-CARRIER-PATH, findings F-PRB-ABSENT-PATH, F-PRB-ABSENT-WRITER)
Option C's sentence "a carrier WITHOUT the field … keeps today's class-context binding" named an outcome without its stage order or its NoHit outcome, and it did not say which writer it applies to. Verified: every self-call carrier on the django before-store was written by `python-core:0.1.0` (14,138 unresolved and 36,307 resolved CALLS rows; `python-extractor/src/extractor.rs:18 EXTRACTOR_NAME`); the resolver receives the edge's `extractor`. The precise rule, replacing that sentence:
1. **Writer check first.** The legacy path applies ONLY to a carrier whose edge `extractor` is exactly `python-core:0.1.0`. A carrier without `receiverBinding` written by the current extractor (`python-core:0.2.0`) or by an unrecognized writer is UNPROVEN: unresolved `self_call_receiver_unproven` with every candidate. Three writer cases, three tests.
2. **What "today's class-context binding" preserves (D-PRB-LEGACY-CARRIER-PATH = A′).** For a verified `python-core:0.1.0` carrier the stage ORDER is HEAD's — the namespace-alias stage first (`resolver.rs:931-980`), the class-hierarchy stage second (`:982-1010`) — so a binding an old carrier produced on refresh is the binding it had; a hierarchy HIT stays static (class-context evidence, as PYTHON-SELF-BINDING-1 ratified). The hierarchy MISS is TERMINAL: unresolved `self_call_hierarchy_miss` with the pool, never the bare-name fall-through — that fall-through is a resolver defect this slice removes for every writer (D-PRB-SCOPE-1 amendment 2), not evidence any carrier carried. Reward: old certain edges rest on the evidence they had; the one evidence-less binding (bare name) is gone on the first refresh; staleness of the carrier itself is visible through the extractor version until rebuild. Risk: a legacy carrier's alias-collision case stays as HEAD had it until rebuild (0 such aliases on django). Rejected: A as literally stated (keeps the bare-name fall-through for old carriers — a name-only binding for a typed receiver, the class this slice exists to remove); B (hierarchy-first for old carriers — grants a stage order the old evidence did not have); C (withhold all old hits until rebuild — removes 36,307 evidence-based bindings on refresh).
3. **Refresh verification** asserts exactly this: on a store indexed by 0.1.0 and refreshed by the new binary, every previously certain self-call edge whose target the hierarchy reproduces stays; every bare-name fall-through row becomes `self_call_hierarchy_miss`; no row becomes `self_call_receiver_unproven` (the writer is 0.1.0). The allocation's §2.1 R1(iii), P-PRB-02, PRB-C01 and the refresh check state the same order and outcomes.
