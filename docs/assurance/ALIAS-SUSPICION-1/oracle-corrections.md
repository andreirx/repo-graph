## A-2 / D-AS1-002 (2026-09-21) — the reason grammar joined module paths with commas (→ INPUT-3)

- **Raised:** by the INPUT-2 implementation review (review-ALIAS-SUSPICION-1-0 of the second admission, codex gpt-5.6-terra), result decision-required — decision D-AS-REASON-ENCODING, finding F-AS-001 (correctness): `alias_isolated_modules=<path>(<n>),…` is emitted by joining paths with `,` and parsed by the renderer with `split(',')`; a module path containing a comma (legal in a directory name) would render a false module name while the Suspicious Modules list shows the true one. The reviewer's options: (1) keep `reasons` as strings but encode unambiguously; (2) a typed structured field on the downgrade DTO.
- **Resolved:** 2026-09-21 by the in-place manager (operator; the human may override) — option 1 in its smallest form: ONE reason string PER evidenced module, count first, path last: `alias_isolated_module=<n> <path>` (parsed with `split_once('=')` then `split_once(' ')`; the count never contains a space, the path takes the remainder verbatim — reversible for every path, including commas, parentheses and spaces). The `reasons: Vec<String>` shape and the `key=value` convention of every other downgrade reason are unchanged (HEAD's reason was `suspicious_zero_connectivity_modules=N`); no DTO field, no JSON-in-a-string. Rejected: a JSON payload after the key (a second grammar inside a string); a structured field (a boundary change the reader does not need).
- **Allocation change (A-2):** §2.1.3 and §2.1.5 grammar and parsing; the literals of AS-C02/C04/C05/C08/C10; two new tests bound — rules `alias_suspicion_reason_survives_commas_parentheses_and_spaces_in_the_module_path` and renderer `downgrades_block_renders_a_module_path_containing_a_comma_verbatim`; the parity fixture's expected reason. The preserved candidate (candidate-2.patch, the accepted-in-all-else INPUT-2 candidate) needs this ONE code change at its second admission.
