## OC-1 (2026-09-21) — PSB-C08's store seam could never match rows across two indexes, and collapsed duplicate call sites (→ INPUT-3)

- **Defect (in the INPUT-2 oracle, not the product):** the seam keyed unresolved rows by the caller node's `stable_key`, which embeds the index's own `repo_uid` (a per-index ULID) — so no row of the `-before` store can equal a row of the `-after` store and every row reads as "moved"; and it stored rows in a dict keyed by (stable_key, target_key, line), which collapses the 700 django rows that share a caller, target and line (one call site emitted more than once). The first admission's candidate passed every product-facing assertion of PSB-C08 (`Callers (0)` → `Callers (2)` with `__call__ … wsgi.py:120` and `… client.py:169`; no `asgi.py`/`exception.py`/`AsyncClientHandler`; `2 callers found`) and the other ten checks; only the seam script exited non-zero.
- **Correction:** rows are keyed by (caller `qualified_name`, caller file `path`, `target_key`, `line_start`) — identities that survive a reindex — and counted as a multiset (`collections.Counter`); "moved" = before − after, "appeared" = after − before; the resolved-CALLS delta must equal the moved count. Verified by the manager on the first admission's before/after stores on 2026-09-21: CALLS 60,414 → 64,354 (+3,940 = the rows that left, all 2-part `self.`/`cls.` keys; none appeared), 4 `self_call_ambiguous_mro` rows incl. `django/contrib/auth/forms.py:576`, callers of `BaseHandler.get_response` exactly `WSGIHandler.__call__` and `ClientHandler.__call__`.
- **Also recorded:** the first admission's candidate checkpoint was refused by the runtime because the two new fixture files were added with `git add -N` (porcelain ` A`, unsupported); the resume note now says `git add` (staged `A `) or untracked (`??`), never intent-to-add.
