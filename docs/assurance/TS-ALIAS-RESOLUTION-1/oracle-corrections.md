# TS-ALIAS-RESOLUTION-1 — oracle and allocation corrections (append-only; recorded for the next baseline, TD-022)

## OC-1 (2026-10-03, operator) — TSA-C04's `OTHER_ROWS` compared the raw `target_key`, which embeds the per-index repo uid
Admission 1's TSA-C04 stopped at `('amodx', 'a non-alias unresolved import row moved')`: four relative `.css` import rows whose `target_key` is a FILE stable key `<repo_uid>:<path>:FILE`; a fresh index has a new ULID uid. Same path, line, category and basis before and after (builder diagnosis, read-only SQL; the reviewer's F-TSA-ORACLE confirms). Correction: the Python that compares `OTHER_ROWS` strips `^repo_[a-z0-9]+:` from `target_key` on both sides (the rule `rg-store-diff.py` already applies to every key and, since agent-manager d36b046, to metadata strings). D-TSA-ORACLE option A. The builder's supplementary run with exactly that change finished `TSA-C04-OK` (416/416, 95/95, storybook edge + module edge, no other movement) — evidence, not the check; the corrected check runs in admission 2.

## OC-2 (2026-10-03, operator) — TSA-C05 item 7's "mechanical initialiser only" rule meets the `INDEXER_VERSION` assertions
The version bump `indexer:1.6.0 → 1.7.0` (section 2.1 item 6) necessarily changes the three literal assertions in `orchestrator.rs:4414-4424` (`assert_eq!(INDEXER_VERSION, …)` and the two `build_toolchain_json` expectations). ## OC-3 (2026-10-03, operator) — the unreadable static reason must reach the served row (F-TSA-UNREADABLE)
Storage decodes a `tsconfig_paths` carrier whose candidate differs from the edge's target to `ImportReason::Unreadable` (`queries.rs` `import_row_reason`); the renderer's `static_row_state` matched only `Recorded` and printed plain `static` for the decoded `Unreadable`, so the admission-1 test (a mismatched `Recorded` row built in the test) never exercised the served seam. Correction to section 2.2 and the renderer: a static row whose reason is `Unreadable` prints `static: reason unreadable (<storage's text>)` — the predicate storage established, in the reader's words — for every basis, because the unreadable state is a property of the carrier, not of one basis; a static row with no reason, or with a readable reason other than `tsconfig_paths`, prints `static` as at HEAD. The byte-identity promise narrows to those rows (no corpus store carries an unreadable static carrier: the admission-1 field run rendered every HEAD static row unchanged). Tests: a storage test decoding the mismatched carrier to `Unreadable` with the exact text, and an rgr test rendering that `Unreadable` variant on a static row, bound as a pair in TSA-C03.

## OC-4 (2026-10-03, operator) — a substitution or `baseUrl` that escapes the repository root binds nothing (F-TSA-OUTSIDE-REPO)
`normalize_join` pops `..` silently at the root, so `{"@x": ["../external/x"]}` on a root tsconfig could match the indexed `external/x.ts` — a static edge to a file the mapping does not select. Correction to section 2.1 item 4: `tsconfig_alias_hits` declines a substitution (and a `baseUrl`) that is absolute or whose `..` segments outnumber the directory segments they pop — no candidate, never a clamp; one negative test per case in the import-resolver suite. `resolve_tsconfig_alias` keeps the HEAD behaviour byte-identical (preserved by TSA-C05(1)); its copy of the gap is filed under ALIAS-SELECTION-PARITY-1.
